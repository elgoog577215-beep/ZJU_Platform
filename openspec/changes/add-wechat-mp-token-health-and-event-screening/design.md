# 公众号登录态验活与活动候选筛选设计

## Token 验活

- 新增服务端轻量只读验活请求，复用当前凭据文件、请求头和微信 MP 可信域名校验。
- 验活结果分为 `missing`、`checking`、`valid`、`expired`，并通过 `reason` 区分 invalid session 与检查请求失败。
- 按产品约定，微信 MP 的 invalid session、登录超时、无效 token、网络错误、超时和 5xx 均归类为 `expired`；不清除本地凭据，后续真实调用成功后恢复为 `valid`。
- 服务端对验活结果做短时缓存，页面轮询不会在每次状态请求中重复打微信 MP。
- 真实文章请求成功或返回失效错误时同步更新验活缓存，保证定时任务失败后网页刷新可以立即看到状态。
- Token 验活任务默认启用、默认间隔 12 小时，服务启动后立即执行一次，间隔可以在现有采集设置中配置。

## 网页状态

- `GET /admin/wechat-mp/status` 返回脱敏凭据与 `health`，不返回 token、Cookie 原文。
- 公众号导入页在初始化和页面停留期间定期刷新状态。
- `expired` 时现有凭据指标显示登录态不可用，扫码登录按钮仍可用；采集操作仍允许真实调用，以便成功后自动恢复。

## 活动候选筛选

- 继续调用现有 `parseWithLLM`，任务仍为 `wechat_event_parse`，不增加第二次模型调用。
- 扩展输出字段：
  - `is_activity_candidate`：是否属于适合活动栏目的活动类推文。
  - `activity_confidence`：0-1 的活动候选置信度。
  - `activity_reason`：简短判断依据。
- Prompt 明确要求：讲座、比赛、培训、报名、志愿、招聘/交流等有明确参与动作或活动信息的内容可以作为候选；新闻报道、成果回顾、政策说明、纯通知且无具体活动安排等内容判为非候选。
- 服务端使用保守阈值 `activity_confidence >= 0.70` 且 `is_activity_candidate = true` 才进入活动表。
- 文章表新增活动筛选状态、原因和关联 `event_id`，确保失败可重试、拒绝可追踪、成功可幂等。

## 活动入库

- 将 AI 解析结果映射到既有 `events` 字段，不新建活动表。
- 以公众号原文链接作为幂等键：已存在关联活动时更新解析字段但保持 `pending`，不存在时创建 `pending` 活动。
- 自动入库不设置 `uploader_id`，不触发已审核内容的关注者推送；管理员在现有活动管理列表中审核。
