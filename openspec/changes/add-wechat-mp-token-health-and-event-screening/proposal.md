# 公众号登录态验活与活动候选筛选提案

## 背景

当前微信 MP 登录态只在真实获取账号或文章时才会暴露失效，管理员在网页上看到的“已登录”可能已经无法使用。同时，定时采集已经能够把公众号文章交给现有 AI 活动解析器，但所有文章都会先成为解析候选，尚未在进入活动栏目之前判断是否确实属于活动类内容。

## 目标

- 在管理员打开公众号导入页并持续停留期间，使用轻量只读请求自动检查微信 MP token 与 Cookie 是否仍然有效。
- 将失效状态直接反馈到现有登录状态区域，允许管理员重新扫码登录。
- 在现有 `wechat_event_parse` AI 调用中增加“是否适合活动栏目”的结构化判断。
- 只有通过活动候选筛选且达到服务端置信度阈值的文章，才写入现有 `events` 表，并统一使用 `pending` 状态。
- 保留公众号增量文章、解析状态和失败重试能力，不增加独立可视化筛选器。

## 非目标

- 不新增独立的活动筛选页面或筛选器。
- 不把活动治理扫描改造成公众号原文筛选器。
- 不自动审核通过或发布活动。
- 不改变现有手动导入文章/活动的按钮语义。

## 验收

- 登录态存在但被微信 MP 判定为 invalid session 时，网页自动显示已过期，不需要先点击抓取文章。
- 登录态检查失败时不暴露 token 或 Cookie，并区分失效与网络暂时不可用。
- 普通新闻、成果报道、政策说明等非活动文章不会写入 `events`。
- 活动候选文章会写入 `events`，状态为 `pending`，并保留原文链接与解析后的活动字段。
- 同一原文重复采集不会重复创建活动。
- AI 返回空结果、低置信度或活动候选为否时，文章仍保留在增量文章库并可追踪原因。
