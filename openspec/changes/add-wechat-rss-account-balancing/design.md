# 设计

账号及凭据继续由 WeWe RSS 数据库管理，主平台不保存微信读书 token。管理员沿用现有登录、启停和删除权限。

文章列表与公众号信息请求共用随机选号方法，每次从当前有效、启用且未限流账号中等概率选择一个，允许连续选中同一账号，不记录上次选择或保证每轮遍历。查询返回后再次排除已限流账号，移除原先最多 10 个候选的限制。

401 保持标记登录失效；WeReadError429 加入当日排除名单，上海时间次日恢复，现有管理员重新启用入口可清除排除。普通网络错误不把账号加入名单。没有可用账号时明确失败，文章读取保留最多 3 次重试，公众号信息不新增重试。

仅限流名单保存在服务实例内存，重启会重置，不提供多副本全局均衡或单账号并发限制，不提高现有采集频率。回滚独立服务代码或镜像即可，无数据迁移。

## 构建与生产部署

GitHub Actions 在独立 wewe-rss 仓库 master 构建 Linux AMD64 运行镜像，运行账号测试并检查应用源码、测试、source map 和开发工具已剔除。镜像推送 GHCR，按提交标签发布并用摘要部署；编译产物、生产依赖及必要迁移文件留在镜像。启动只运行本地 Prisma，不下载依赖。

生产 Compose 只用 image，不包含 build；固定项目名 wewe-rss-beta 和现有外部数据库卷 wewe-rss-beta_wewe-rss-beta-db。应用限制 512 MB 内存、0.5 CPU、128 PID，Node 堆为 320 MB，日志 10 MB × 3。数据库仍沿用原容器和数据。Feed 默认 metadata；健康检查只访问根入口，采集 smoke 限定单条 metadata，不能以全量全文 Feed 验证健康。

部署脚本校验摘要和旧镜像，拉取成功后备份数据库，仅替换 app；健康失败恢复旧应用镜像，不自动覆盖数据库。生产不执行 Docker build、依赖安装或完整编译。先验证镜像及主平台连接，再由用户补充两个有效账号完成真实随机分配验收。

公开镜像优先将 ghcr.io 替换为南大官方 ghcr.nju.edu.cn，路径和摘要保持不变；不修改 Docker 全局设置，不向镜像站发送 GHCR 凭据。镜像源不可用时可校验 CI artifact 的成品镜像包并按本地镜像 ID 部署，仍禁止生产构建。
