# add-wechat-webview-miniapp

## 背景

当前平台已经有完整的 React/Vite 网站、Express API、移动端导航、PWA/Android/iOS WebView 包装经验和统一内容后台。用户希望优先进入微信小程序生态，同时保持网站内容更新后自动同步到小程序。

纯原生或 Taro 重写会带来路由、样式、状态、富文本、上传、后台和权限体系的重复建设；纯 `web-view` 又会遇到微信审核、业务域名、下载入口、PWA 缓存、新窗口和原生能力边界。更合适的第一期路径是：用微信小程序 `web-view` 承载网站主体，并预留微信登录、订阅消息等原生 API 桥接页。

## 目标

- 新增微信小程序壳工程，默认通过 `web-view` 加载 `https://tuotuzju.com/events?miniapp=1&utm_source=wechat_miniprogram`。
- 复用现有网站、后端 API 和数据库，确保网站后台内容更新后小程序自动同步。
- 在小程序壳内建立路径白名单、加载失败兜底页、登录桥接页和订阅桥接页。
- 网站端识别小程序 WebView 运行态，隐藏或禁用不适合微信审核和 WebView 的入口，例如 App 下载、PWA 安装、后台入口和下载页。
- 接入微信小程序登录桥接：由原生页调用 `wx.login`，后端使用 `code2Session` 换取 openid，并复用现有网站用户表与 JWT 登录态。
- 为后续接入微信登录、订阅消息、分享和逐步原生化保留清晰边界。

## 不做范围

- 不重写 Taro/原生核心页面。
- 不新增第二套内容数据库或平行账号体系；只新增微信 openid 到现有 `users` 的绑定表。
- 不在本轮接入真实微信 `AppID`、`AppSecret`、订阅模板 ID 或代码上传密钥。
- 不提交微信后台配置、认证、备案、审核或远程上传操作。
- 不改变现有网站后台作为唯一内容管理入口的定位。

## 用户可见影响

- 小程序打开后优先进入活动页，活动、文章、项目等内容直接复用网站。
- 小程序内不再展示 App 下载/PWA 安装这类不适合 WebView 审核的入口。
- 小程序加载失败时展示兜底页，用户可重试或回到活动页。

## 风险与回滚

- 微信 `web-view` 仅支持非个人主体小程序，且必须配置业务域名；如果主体或域名不满足，需暂停上线或改走 Taro/原生方案。
- `web-view` 每个页面只能承载一个网页容器，无法在网页上叠加原生按钮；微信原生能力必须通过桥接页完成。
- 如果上线后出现审核或体验问题，可仅回滚 `wechat-miniprogram/` 和小程序模式适配代码，不影响网站主功能和数据库。

## 验收

- OpenSpec 校验通过。
- 微信小程序工程可导入开发者工具，`pages/webview/index` 能生成合法 WebView URL。
- 小程序路径白名单能拦截 `/admin`、`/download`、`/api` 等不开放路径。
- 网站在 `?miniapp=1` 下识别为小程序运行态，并隐藏下载/PWA相关入口。
- `npm run build` 通过。
