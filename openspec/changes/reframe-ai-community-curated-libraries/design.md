## Context

`/articles` 当前由 `AICommunity` 承载，`CommunityPosts` 在第一层提供学习区、资源区和讨论区，学习区再展开十二章路径。底层内容来自既有文章与社区帖子接口，资料区已经支持课程、教师、学期、资料类型筛选和统一投稿；旧 `tab`、`postTab`、`id`、`post` 等参数仍承担外部深链兼容。

本轮改变的是前台第一层心智和内容呈现顺序，不改变社区内容、审核、归属、通知或数据库合同。用户确认 AI 社区采用类似公众号作者或垂直 UP 主的运营方式：不追求全品类数量，而是长期维护少数有用的专题资料库。

## Goals / Non-Goals

**Goals:**

- `/articles` 首屏在桌面和移动端只呈现四个大型可点击入口，其中三个对应资料库，一个对应社区共建。
- 用户选择入口后，四个入口保持同一对象身份并收缩为顶部选择栏；操作栏和内容在动画之后进入。
- 新生资料库先在站内建立上下文，再安全跳转 ima；链接缺失或不合法时给出明确状态和恢复说明。
- 期末资料库与 AI 学习库复用现有数据和交互，不复制内容真源。
- 社区共建作为第四个入口承接讨论；搜索、上传和提问在工作态顶部保持可发现，但不在初始态与四入口争夺注意力。
- 保留旧社区深链、详情和 legacy query 的可恢复访问。

**Non-Goals:**

- 不新增数据库表、社区 API、审核状态或后台内容池。
- 不重做全站导航、主题系统、项目广场、浙客松或用户中心。
- 不在没有真实内容时编造文章数量、维护日期或 ima 分享地址。
- 不把新生资料和期末资料描述为 AI 社区之外的独立产品。

## Decisions

### 1. 默认路由变为资料库首页，具体能力继续使用 query 深链

`/articles` 无社区深链参数时展示资料库首页；三个专题分别使用 `library=freshman|finals|ai`。旧 `area`、`tab`、`postTab` 和详情参数仍优先进入原有内容能力，避免收藏、搜索结果和外部分享失效。

选择 query 而不是新增三个顶级路由，是因为三个资料库仍属于同一 AI 社区入口，需要共享返回链、SEO 和移动端导航；同时 query 状态可复制、可返回、可兼容旧链接。

### 2. `/articles` 采用四入口 Progressive Dock，而不是说明型资料库首页

页面继承现有全站导航、白昼/夜间主题、生态靛蓝和内容背景。AI 社区内容区初始态只显示四个大型入口：新生资料库、期末资料库、AI 学习库和社区共建。每个入口整块可点击，使用大图形、名称、承载状态和一句功能性说明，不显示独立页标题、统计、次级按钮或额外解释段落。

选择任一入口后，四个入口不卸载重建，而是通过共享布局动画收缩为工作区顶部选择栏；当前入口高亮，其他入口仍可直接切换。上下文操作栏和真实内容在入口收缩后出现。该表面属于 Operate 模式，视觉改造只属于 `/articles`，不修改 `DESIGN.md` 的全局世界。

### 3. 新生资料库使用可配置外链与完整不可用状态

通过 `VITE_AI_COMMUNITY_FRESHMAN_IMA_URL` 读取分享地址，只接受 `http:` 或 `https:`。有效时使用新标签页打开并保留 `noopener noreferrer`；缺失或非法时禁用主按钮，显示“链接待配置”及反馈/返回方式。

不使用 ima 官网首页作为假分享链接，因为它不能把用户带到目标资料库，也无法证明具体资料可用。

### 4. 站内资料库只做前台组合，不复制内容真源

期末资料库继续渲染 `CommunityMaterials` 并带入课程资料筛选；AI 学习库继续渲染 `LearningArea`。`CommunityPosts` 增加固定分区模式，允许上层资料库路由隐藏旧三区导航，同时旧入口仍可按原模式渲染。

AI 学习路径在无明确 `lesson` 深链时优先展示已有文章的章节；空章节不再占据默认导航。显式深链仍可打开空章节并看到原有空状态。

### 5. 社区共建成为第四个入口，不新增内容真源

“社区共建”使用 `library=community&area=discuss`，继续渲染现有讨论能力，不建立新的内容类型、帖子表或审核链。提交资料仍进入现有期末资料页并使用既有登录、上传、审核流程；管理员后台、统一编辑器和审核 API 不变。

### 6. 动画表达同一对象的状态变化

四个入口在初始态和工作态使用同一组 DOM 与稳定 key，通过 Framer Motion layout animation 改变尺寸、位置和内部信息密度。选择后的内容使用一次延迟进入；切换入口时顶部选择栏保持稳定，只替换操作和内容。浏览器返回 `/articles` 时播放反向展开。`prefers-reduced-motion` 下取消形变延迟并直接切换，URL、焦点和内容可用性不依赖动画完成。

### 7. 工作态顶部只显示当前可用操作

- 期末资料库：搜索当前资料、上传资料、提出问题。
- AI 学习库：搜索当前内容、提出问题。
- 社区共建：搜索讨论、发起讨论、上传资料。
- 新生资料库：显示 ima 链接状态；只有真实分享地址可用时提供打开操作。

搜索操作聚焦当前内容区的真实搜索框；上传和提问继续触发现有登录、编辑器和审核流程，不复制新的按钮业务逻辑。

### 8. 四入口使用非对称知识汇流台，不使用同质应用卡片阵列

四个入口继续是页面初始态的唯一操作，但桌面端不再使用四张等宽、等高、同构的“图标 + 标题 + 说明 + 箭头”卡片。入口按照内容角色形成非对称布局：AI 学习承担主视觉，新生与期末承担两类明确资料任务，社区共建承担横向汇流任务；四者通过同一套轨迹、节点和响应式布局被识别为一个 AI 社区，而不是四个互不相关的应用。

每个入口使用与其任务一致的几何图形语言，不展示无意义的 `01–04` 编号、重复的“进入”文案或为了填充空间而增加的统计。外层不再使用与卡片重复的厚重边框和大阴影。视觉层级由尺寸、位置、字体和唯一主色完成，保持全站深海蓝、靛蓝、青色和现有圆角体系。

工作态在桌面端收缩为单行命令栏：四个入口位于左侧，当前操作位于右侧；移动端保持四入口同屏，并在下一行显示紧凑操作。初始态到工作态仍使用同一组 DOM 和共享布局动画，视觉重构不得破坏 URL、返回链、搜索聚焦、上传、提问和 reduced-motion。

## Risks / Trade-offs

- [ima 分享地址暂缺] → 使用可配置变量和诚实禁用状态；取得真实分享地址后无需改组件结构。
- [旧链接参数组合复杂] → legacy 参数优先于默认首页，继续运行现有迁移逻辑，并在浏览器验收典型深链。
- [隐藏空章节可能让学习范围看起来变少] → 这是本轮有意的供给收缩；显式深链和未来新增内容仍会恢复对应章节。
- [四入口容易退化为通用图标卡片] → 以用户提供的应用 Dock 为视觉参考，使用大型图形、丰富但克制的层次和共享形变；不增加无用标题、统计或说明区。
- [共享动画影响返回或可访问性] → 状态由 query 决定，动画只表达状态；保留键盘焦点、浏览器历史和 reduced-motion 降级。
- [外部 ima 离开站点] → 先显示站内简介、外部平台标识和返回路径，新标签打开，不覆盖当前页面。

## Migration Plan

1. 先加入资料库首页和 query 分发，不删除现有学习、资料、讨论组件。
2. 调整默认 `/articles` 与三个专题入口，验证旧 `area`、`tab`、`postTab` 和详情深链。
3. 更新 locale、产品蓝图与产品状态，运行 OpenSpec 验证、相关 ESLint 和构建。
4. 在同一数据状态下完成桌面和 390px 移动截图对比。
5. 如需回滚，回退本 change 的前端、locale 和文档文件；数据库与 API 无迁移，无需数据恢复。
