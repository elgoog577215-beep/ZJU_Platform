## Context

`ProjectPlaza.jsx` 当前同时承担数据读取、URL 赛事范围、项目筛选、两套互斥头部、作品网格、详情、发布表单和投稿弹层。`competition` 是否存在被直接用来切换大段 DOM，造成用户选择赛事后原赛事导航消失，页面层级、行动位置和返回路径随状态改变。页面已有真实项目与赛事数据、成熟弹层和黑客松视觉资产，本轮应保留这些能力，但替换主页面的状态组织与布局。

## Goals / Non-Goals

**Goals:**

- 用一套稳定页面骨架承载全部项目和任意赛事范围。
- 让当前范围、可选范围和撤销路径始终同时可见。
- 把赛事事实、投稿状态和相关入口收敛为从属上下文，而不是第二套页面。
- 让搜索、排序、筛选和结果区域在切换范围时保持位置稳定、状态可解释。
- 提升桌面和移动端的扫描效率、键盘可用性、加载反馈和中英文适配。

**Non-Goals:**

- 不修改项目、赛事作品、审核、收藏、分享或身份归属的数据合同。
- 不新增项目广场路由、前端状态库或外部依赖。
- 不重做详情、长期项目发布和赛事投稿表单的业务流程。
- 不补造历史魔搭链接，也不改变现有公开数据。

## Decisions

### 1. 页面采用稳定四层骨架

页面固定为：项目中心介绍栏 → 常驻赛事索引 → 可选赛事上下文 → 发现工具栏与作品工作区。赛事切换只改变选中态、上下文内容和数据结果，不卸载赛事索引或替换页面头部。

选择该结构，是因为用户的核心任务是持续浏览和比较，范围选择必须像目录而不是一次性入口。相比继续维护通用/赛事两套头部，它减少条件分支，也让桌面与移动端共享同一语义顺序。

### 2. URL 是赛事范围的唯一恢复真源

`competition` 查询参数继续决定 `all | event(slug)`。组件从 URL 派生当前范围；点击赛事只更新该参数。搜索和排序在赛事切换时保留，以支持跨赛事比较；仅适用于长期项目的 `progress` 与 `need` 筛选在进入赛事范围时清空并关闭高级筛选，避免产生不可解释的零结果。

不引入额外全局 store，因为该状态只属于 `/projects`，现有 React Router 已能提供深链、刷新恢复和浏览器返回。

### 3. 赛事导航与赛事上下文分离

赛事索引始终显示“全部项目”和所有公开赛事，并为当前项设置 `aria-current`。赛事上下文面板只在选择赛事时出现，展示标题、日期、作品数、投稿阶段、赛事现场和影像档案；长期项目发布始终保留为次级行动。

这样避免“选择器既是入口又是标题”的角色冲突。移动端赛事索引横向滚动，选中项通过 DOM ref 自动滚入视野，但不隐藏其他选项。

### 4. 作品工作区采用稳定目录网格

移除依赖 `nth-child` 的大小随机网格，改为一致卡片尺寸和三列/两列/单列断点。奖项、进度、作者、专业、仓库和部署证据继续按来源显示；结果区新增当前范围标题、结果计数和可清除查询提示。加载使用骨架卡，空态区分“无数据”和“当前条件无匹配”。

一致网格牺牲少量海报式戏剧性，换取跨 24 个以上项目持续浏览时更可靠的比较和扫描。

### 5. 保留既有黑客松视觉世界，降低装饰对操作的干扰

继续使用既有深色黑客松背景、荧光绿品牌强调、字体和全局导航；缩短首屏大标题占用，让常驻赛事索引和作品结果更早进入视野。品牌色仅用于主要行动、当前选择和状态，不用于无意义装饰。

页面按 Operate 模式实现：标准按钮、输入、链接、焦点和 150–250ms 状态过渡优先于展示性动效，并尊重 `prefers-reduced-motion`。

### 6. 组件边界围绕页面任务拆分

保留 `ProjectPlaza` 作为数据、URL、弹层和副作用协调者；新增纯展示组件承载页面介绍、赛事索引、赛事上下文、工具栏、结果头、骨架与网格。详情和表单继续复用现有实现，避免把视觉重构扩张到数据写入链。

## Risks / Trade-offs

- [赛事数量增长后横向索引过长] → 桌面允许横向滚动，移动端自动将当前项滚入视野，并保持“全部项目”首项可直接返回。
- [切换赛事时清空进度/需求筛选可能让用户意外] → 只清空对赛事归档无意义的筛选，保留关键词和排序，并在 UI 中明确高级筛选属于长期项目。
- [统一卡片尺寸降低获奖项目视觉突出度] → 用奖项与名次标记提供语义层级，不用尺寸破坏目录稳定性。
- [现有 1700 行组件重构易影响弹层行为] → 主页面与详情/表单分层改动，保留现有数据函数和弹层接口，并回放深链、收藏、投稿和返回关闭。

## Migration Plan

1. 先增加纯展示组件和新样式，再将现有数据与动作接入稳定骨架。
2. 删除旧的通用/赛事互斥头部和 `nth-child` 网格规则，保持 API 请求与弹层行为不变。
3. 运行 lint、构建、相关测试和严格 OpenSpec 校验。
4. 在本地真实浏览器验收全部项目、选择赛事、返回全部、搜索、筛选、详情、中文、英文、桌面和 390px 移动端。
5. 若上线后出现回归，可回滚本变更前端与 i18n 提交；无需恢复数据库。

## Open Questions

无阻塞问题。未来赛事数量显著增加时，可在独立变更中把横向赛事索引升级为可搜索归档目录。
