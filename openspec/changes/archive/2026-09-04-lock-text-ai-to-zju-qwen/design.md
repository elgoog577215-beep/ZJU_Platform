## Context

`aiModelConfigService.js` 同时承担后台模型配置、环境变量兜底和真实调用选路。生产数据库当前已有自建 `qwen3.8-27b` 配置，因此活动助手真实返回正确模型；但代码默认仍是魔搭，后台也能创建任意文本端点。数据库现场高于环境变量的现状使“现在可用”不能自动变成“以后不会漂移”。

文本角色包括 `general`、`fast`、`reasoning`；`embedding` 是不同能力，不能伪装成 `qwen3.8-27b` 文本调用。所有配置仍不得连接魔搭或 DeepSeek。真实私有地址和凭据不得进入 Git、日志或接口响应。

## Goals / Non-Goals

**Goals:**

- 文本调用只使用 `ZJU_QWEN_BASE_URL` 指定的私有端点和精确模型 `qwen3.8-27b`。
- 缺少锚点、配置漂移或后台误操作时，在发起网络请求前失败。
- 保留同一节点内现有有界重试和业务级本地失败结果，不再跨文本提供方切换。
- embedding 保持显式角色，不允许魔搭或 DeepSeek 地址。

**Non-Goals:**

- 不修改赛事作品和生态伙伴中的“ModelScope 魔搭社区”展示数据。
- 不把 `qwen3.8-27b` 冒充 embedding 模型。
- 不在 Git 中保存服务器地址、账号、API key 或数据库密文。

## Decisions

1. 新增集中政策函数。文本配置规范化 URL 后必须等于 `ZJU_QWEN_BASE_URL`；过渡期允许该锚点从现有 `LLM_BASE_URL` 读取，但没有任何默认公网地址。模型 ID 固定为 `qwen3.8-27b`。相比只删除默认值，这能同时约束数据库配置和后台写入。

2. `createConfig`、`updateConfig`、`testConfig`、`getEnabledConfigs` 与 `callChatCompletion` 都执行同一政策。写入时拒绝错误配置，选择时过滤历史漂移配置，调用前再做最后防线。相比只在后台表单校验，这能覆盖环境变量、旧数据库和直接服务调用。

3. 所有角色先拒绝魔搭与 DeepSeek 主机；文本角色再要求精确私有锚点和模型。embedding 继续使用既有显式角色配置，可以指向其他已授权的自建 embedding 节点，但不能自动借用 general 配置，也不能连接被禁止的外部主机。

4. 不自动删除历史数据库行。违规配置保留供管理员审计，但不参与运行；后续显式更新时必须改成合规配置。相比启动时破坏性迁移，这样保留可恢复性和现场证据。

5. 生产验收使用公开活动助手真实请求，要求 `modelStatus.used=true`、`fallbackUsed` 不为真、`model=qwen3.8-27b`，同时执行代码测试。仅查看配置列表或健康接口不能证明真实路径用了模型。

## Risks / Trade-offs

- [生产只设置旧 `LLM_BASE_URL`] → 过渡期将其作为私有锚点；示例和长期规则改用 `ZJU_QWEN_BASE_URL`，后续部署可平滑补齐。
- [历史文本配置被过滤后无可用模型] → 显式返回既有“模型未配置/本地结果”状态，不回退外部提供方；发布前先验证当前生产真实路径。
- [embedding 配置与文本规则混淆] → 保留既有 role 隔离测试，并新增外部主机拒绝测试。
- [错误信息泄露私有地址] → 错误只返回稳定政策代码，不拼接原始 URL 或 key。

## Migration Plan

1. 在当前生产真实请求上确认自建模型已使用。
2. 增加政策、测试、示例和规则；本地运行相关服务测试与 OpenSpec 严格校验。
3. 推送 `master`，等待现有 GitHub Actions 生产发布。
4. 验证部署提交、HTTPS、服务健康和公开活动助手真实模型状态。
5. 如发布失败，使用现有生产备份和上一版本回滚；回滚只恢复服务，不重新授权魔搭文本路由。
