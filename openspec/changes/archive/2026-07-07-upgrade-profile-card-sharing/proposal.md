## Why

个人主页和组织主页已经具备 profile 身份底座，但当前更像“资料页”和“内容聚合页”，还不是可以被发到微信群、活动群、招新群、合作沟通里的数字名片。用户需要未来能发送个人名片、社团名片和组织名片，形成类似 Bonjour 数字名片的传播入口。

第一期不做 NFC、小程序原生页、访客分析和通讯录交换，先把 Web/PWA 内已有个人/组织主页升级成“能看懂、能扫码、能回流”的分享闭环。这样可以复用现有 `profiles`、`profile_members`、个人 profile card、组织归属和项目海报能力，不创建平行身份系统。

## What Changes

- 优化 `/u/:handle` 与 `/org/:handle` 的首屏信息结构，让访问者在第一屏理解“是谁、在做什么、我能怎么继续互动”。
- 为个人 profile 和组织 profile 增加统一“分享名片”入口。
- 新增 profile 分享名片预览弹层，展示头像或 logo、名称、handle、身份类型、认证状态、简介、精选标签、主页链接和二维码。
- 分享名片支持复制主页链接、下载 PNG、浏览器原生分享；二维码指向对应公开主页。
- 个人名片优先读取已有个人 profile card、社交链接和公开标签；组织名片优先读取 profile 基础信息、组织类型、认证状态和公开归属数据。
- 新增中英文文案，并通过 i18n 读取。

明确不做：

- 不做 NFC 实体卡绑定。
- 不做微信小程序原生名片页。
- 不做名片互换、通讯录、访客记录或增长分析。
- 不把隐藏联系方式、隐藏自定义卡片或登录后才可见的信息写入分享图片。
- 不新增脱离 `profiles` 的“名片账号”或组织账号模型。

## Impact

- 前端：
    - `src/components/ProfilePage.jsx`：优化个人/组织主页首屏，增加分享名片入口。
    - 新增 profile 分享名片组件，复用现有二维码、PNG 导出、复制链接和原生分享思路。
    - 补充响应式样式，保证桌面端和微信内移动端可读。
    - `public/locales/zh/translation.json`、`public/locales/en/translation.json`：新增文案。
- 后端：
    - 第一期开销尽量保持前端聚合，不新增数据库表。
    - 如现有 profile 响应缺失分享所需的公开字段，只补公开只读字段，不改变权限模型。
- 验证：
    - OpenSpec validate。
    - 前端 build 或 lint。
    - 浏览器 smoke 检查个人页、组织页、分享弹层、二维码渲染、复制链接、PNG 下载和移动端布局。
