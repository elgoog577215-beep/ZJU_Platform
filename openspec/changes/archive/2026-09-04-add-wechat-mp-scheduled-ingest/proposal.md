# add-wechat-mp-scheduled-ingest 提案

## 背景

现有微信 MP 后台能力已经支持管理员扫码登录、检索公众号文章、抓取正文并进入解析流程。但运营场景需要长期维护一组公众号，并每天自动增量抓取新文章内容，避免管理员重复手动检索。

## 目标

- 在后台维护可启停的公众号列表，支持单个录入和文件上传解析。
- 增加每日定时增量采集任务，开始时间、分页数量、正文抓取和等待参数可配置。
- 支持管理员手动触发一次增量采集，并查看任务运行记录与新增文章。
- 在批量账号、自动翻页和正文抓取之间插入随机等待，默认采用 55-120 秒查询间隔，降低错误配置和高频访问风险。

## 非目标

- 不在本次变更中自动创建或发布活动。
- 不实现分布式任务队列；当前以单进程 Node 定时器和 SQLite 持久化记录为边界。
- 不把微信 MP 原始登录凭据暴露给前端。

## 风险与约束

- 微信 MP 登录态可能过期，定时任务需要记录失败并提示管理员重新扫码。
- 采集间隔过短可能触发平台风控，后台配置必须带专业提示并提供保守默认值。
- 定时器是单进程实现，多实例部署时需要后续引入任务锁或统一调度。

## 验收标准

- 管理员可以保存每日定时配置，并看到默认 55/120 秒查询间隔。
- 管理员可以上传 JSON/CSV/TSV/TXT 格式公众号列表并解析入库。
- 管理员可以手动触发增量采集；任务在后台执行并记录运行状态。
- 定时任务按配置时间触发，增量保存新文章和正文，重复链接不会重复插入。
- 后端测试覆盖配置、导入解析、增量去重和随机等待注入。
