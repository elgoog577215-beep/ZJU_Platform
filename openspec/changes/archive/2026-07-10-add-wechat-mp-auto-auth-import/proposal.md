# add-wechat-mp-auto-auth-import 提案

## 背景

当前平台已经支持在上传活动时粘贴微信公众号文章链接，并通过 `POST /api/resources/parse-wechat` 抓取正文、调用统一 AI runtime 解析成活动字段。但这个流程依赖管理员或用户先手动拿到文章链接；遇到需要登录微信公众平台后台才能稳定获取文章列表、公开页面直接抓取失败、或需要批量从指定公众号挑选活动文章时，现有能力不够。

相邻项目 `../scrape-hub` 已经实现了微信公众平台 MP 登录态管理、二维码登录、token/cookie 捕获、公众号 fakeid 搜索、文章列表获取和正文抓取。这个 change 的目标是在本项目后台复用其核心思路，补齐“鉴权 -> 获取文章链接 -> 获取正文 -> 渲染预览 -> 进入现有解析链路”的管理闭环。

## 目标

- 在管理员后台新增微信 MP 采集入口，让管理员可以发起二维码登录并在页面中看到二维码。
- 后端使用无头浏览器打开微信公众平台登录页，捕获登录后的 token 和 Cookie，并安全保存到服务器私有数据目录。
- 扫码登录是本能力的强依赖；部署环境必须安装 Playwright 及 Chromium，缺失时后台应明确报错而不是静默降级。
- 登录态可用于搜索公众号、获取文章列表、抓取文章正文和封面。
- 管理页面可以展示文章列表与正文预览，并将选中文章送入现有微信活动解析链路。
- 所有新增用户可见文案同步中文和英文。

## 非目标

- 不提供给普通用户使用的公开微信登录或 OAuth 能力。
- 不把微信 MP token、Cookie、完整浏览器 profile 或二维码截图写入仓库。
- 不在本轮批量自动创建活动记录；本轮只做到抓取、预览和复用现有解析结果。
- 不重写现有 `UploadModal` 的手动粘贴链接入口；它继续作为轻量入口存在。
- 不承诺绕过微信平台风控；若微信要求重新扫码，后台应提示重新登录。

## 用户可见影响

- 管理员后台新增“微信采集”模块。
- 管理员可以点击“开始扫码登录”，页面展示后端无头浏览器截取到的二维码。
- 登录成功后页面显示脱敏状态，不显示 token 或 Cookie。
- 管理员输入公众号名称和可选关键词后，可以拉取文章列表。
- 点击文章后可预览标题、作者、摘要、正文文本和封面，并可执行“解析为活动字段”。

## API 与数据影响

- 新增仅管理员可访问的 `/api/admin/wechat-mp/*` API。
- 后端新增微信 MP 服务，负责浏览器登录、凭据保存、登录态测活、公众号搜索、文章列表和正文抓取。
- 凭据和浏览器数据保存在 `server/data/wechat-mp/` 之下；该目录已被 `.gitignore` 的 `server/data/` 覆盖。
- 不新增数据库表；审计可复用现有 `ai_assistant_runs` 记录解析动作。

## 风险与回滚

- 风险：微信 MP 登录页面和后台接口是平台私有页面/API，可能变更。缓解：服务层集中封装选择器、接口和错误码，前端给出重新登录提示。
- 风险：token/cookie 泄露。缓解：原始凭据仅写入服务器私有文件，API 永不返回原始值，日志只记录脱敏状态。
- 风险：后台无头浏览器占用资源。缓解：同一时间只允许一个登录会话，超时自动关闭，可手动取消。
- 风险：部署环境缺少 Chromium。缓解：将 Playwright 写入后端依赖，并在后台状态接口和登录启动前做强校验。
- 风险：抓取频率过高。缓解：默认分页数量和请求间隔受控，后续可加后台限流。
- 回滚：移除新增后台模块、路由和服务文件即可；没有数据库迁移或数据破坏性变更。
