## Why

项目广场当前把“全部项目”和“单场赛事”渲染成两套互斥页面结构，用户选择赛事后，赛事选择器会直接消失，搜索、投稿、返回和当前范围也随布局切换而漂移。继续局部修补会扩大条件分支，因此需要以稳定状态模型和统一页面骨架整体重构。

## What Changes

- 将 `/projects` 重构为始终稳定的“赛事档案索引 + 作品工作区”，不再按是否选中赛事替换整套头部与导航。
- 让“全部项目”和全部公开赛事在任意范围内始终可见，当前选中态明确，且可通过 URL 恢复和撤销。
- 把赛事日期、作品数、投稿状态、赛事现场与影像入口收敛到独立上下文面板；该面板只补充当前赛事，不拥有全局导航。
- 固定搜索、排序、筛选、结果标题和投稿入口的相对位置，明确哪些筛选适用于全部项目，哪些状态随赛事切换重置。
- 将作品墙改为稳定、可扫描的统一档案网格，并补齐加载、空态、焦点、移动端横向赛事索引和中英文状态文案。
- 保留现有项目详情、收藏、分享、长期项目发布和赛事投稿能力，不修改项目与赛事成果的数据真源、审核、权限或 API 合同。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-plaza`: 修改项目广场的页面状态、赛事导航持久性、上下文层级、筛选适用范围和响应式交互要求。

## Impact

- 主要影响 `src/components/ProjectPlaza.jsx`、`src/components/projectPlaza.styles.js` 和 `public/locales/{zh,en}/translation.json`。
- `/projects?competition=<slug>` 继续作为赛事范围的唯一可恢复 URL；不新增路由，不修改后端 API 或数据库。
- 项目详情、投稿弹层和分享海报只在需要适配新页面入口时调整连接方式，不改变其业务行为。
- 回滚可直接恢复本变更涉及的前端、i18n 与规格文件；数据和生产 schema 不受影响。
