# add-wechat-read-rss-source 提案

## 背景

主仓库目前已经有微信公众号直连采集链路：管理员扫码登录微信 MP，检索公众号文章，抓取正文，再进入 AI 提取、活动初筛和人工审核。该链路依赖浏览器登录态和微信 MP 请求节奏，维护成本高，不能作为唯一的长期采集实现。

WeWe RSS 已在独立服务中通过微信读书账号维护公众号订阅，并输出 Atom/RSS/JSON。主仓库需要复用现有的文章库、AI 提取、活动初筛、审核和归属链，只替换文章获取来源。

## 目标

- 在现有微信 MP 增量采集链中增加 `wewe_rss` 来源类型。
- 通过受信任的 WeWe RSS 服务读取公众号 feed，并优先消费其全文内容；新增来源默认使用 RSS，多个启用来源中 RSS 优先执行。
- 将标题、原文链接、作者、发布时间、封面、正文和图片映射到现有 `wechat_mp_ingest_articles`。
- 复用现有 `parseWithLLM`、活动初筛、治理触发和管理员候选内容界面。
- 支持按 feed ID 配置来源，避免在主仓库保存微信读书登录凭据。
- 保持重复链接去重、失败可重试和人工审核，不自动公开发布。

## 非目标

- 不在 ZJU_Platform 中保存微信读书 token 或直接实现 WeRead 原始接口抓取；登录和管理请求通过受保护的 WeWe RSS 后端 API 代理。
- 不直接重新抓取 `mp.weixin.qq.com` 正文；WeWe RSS 的全文输出是本方案的正文来源。
- 不新增第二套文章、活动、AI prompt 或审核数据表。
- 不因 RSS 获取成功而自动创建已审核文章或公开活动。
- 不允许管理员输入任意 URL 作为抓取目标；来源只接受受信任 HTTPS 基地址下的 feed ID。

## 用户可见影响

- 管理员可以在现有“内容采集”后台直接完成微信读书扫码、账号管理、订阅源管理和文章刷新；采集源配置仍使用 WeWe RSS feed ID。
- 管理员新增来源时默认选择“微信读书 RSS”；直连微信 MP 来源仍可作为兼容/备用来源。
- 主平台后端提供统一的 `/api/admin/wechat-rss/*` 管理 API，浏览器不再需要直接访问 WeWe RSS Dashboard 或携带其授权码。
- WeRead RSS 来源不要求主仓库扫码登录微信 MP；直连微信 MP 来源仍保留。
- 候选文章、AI 提取状态、活动初筛和后续人工审核入口保持不变。

## 验收

- 已启用的 WeRead RSS 来源可以在手动和每日任务中读取 Atom/RSS 全文 feed。
- 当 RSS 与直连微信 MP 来源同时启用时，任务 SHALL 先执行 RSS 来源，再执行直连来源。
- Feed 项目能被解析为现有增量文章记录，并保留微信公众号原文链接。
- 重复执行不会重复插入文章；已完成 AI 提取的文章不会重复调用模型。
- WeWe RSS 请求失败、格式错误或正文为空只影响对应来源，并记录可重试错误。
- WeRead RSS 管理 API 失败不会泄露服务端授权码或读书账号 Token。
- WeRead RSS 任务不要求微信 MP 浏览器登录态，也不会调用直连微信 MP 的 fetchArticleContent。
- 现有直连微信 MP 来源、活动审核链和其他后台功能回归通过。
