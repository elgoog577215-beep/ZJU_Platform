## Context

当前 `/hackathon` 由 `HackathonSeasonOne` 组合报名页与成果页。历届赛事使用横向时间轴，报名/成果使用第二组横向按钮，整个控制条还会在内容滚动超过 96px 后隐藏。`ProjectPlaza` 和 `MediaEventArchive` 是独立整页组件，各自读取不同的 URL 参数并再次渲染赛事选择器，因此直接嵌套会产生三套范围状态和重复导航。

赛事模板已经提供稳定的 `event.key` 与 `results.competitionSlug` 映射；项目、赛事作品、图片和视频也已有正式 API 与关联。本次只重组前端应用壳和路由状态，不改变数据真源。视觉继承现有“公共实验场”系统与黑客松青柠强调色，不推翻报名、项目、影像和成果内容本身的领域表达。

## Goals / Non-Goals

**Goals:**

- 让用户始终看见当前赛事、当前环节以及可以切换到哪里。
- 用一个赛事上下文承载报名、项目作品、赛事影像和成果展示。
- 在桌面端将赛事选择与环节选择分为垂直、水平两条正交轴；在移动端压缩为赛事选择器与可横向浏览的四环节栏。
- 复用现有项目、投稿、图片直播、精选和成果内容，并保持历史深链可恢复。
- 删除滚动触发的工作区导航隐藏行为，避免选择栏消失。

**Non-Goals:**

- 不修改项目、赛事作品、图片、视频或 competition 的数据模型。
- 不重做报名页、作品卡片、上传弹层或成果章节的业务内容。
- 不把活动集合并入浙客松，也不把所有通用媒体强制归属某场赛事。
- 不在本次增加新的后台赛事阶段配置；四个公共环节保持稳定，动作可用性继续依据现有模板与 competition 状态判断。

## Decisions

### 1. 外层工作区唯一拥有赛事选择

`HackathonSeasonOne` 继续作为 `/hackathon` 的唯一编排器，并由它根据 `event.key` 选出模板和 `competitionSlug`。桌面外层采用 `252px + minmax(0, 1fr)` 网格：左侧是紧凑赛事档案卡，右侧顶部是四环节栏，正文只渲染当前环节。

项目和影像组件增加受控嵌入模式，接收外层 `competitionSlug`，不再渲染自己的赛事选择器。独立 `/projects` 和 `/media` 仍保持原行为。相比在三个页面之间互相跳转，这能保证范围选择只有一个所有者；相比把全部功能复制进新组件，这能保留正式业务实现。

### 2. 四环节是稳定工作区，不是互斥状态机

四个环节固定为 `register`、`projects`、`media`、`showcase`。栏目永不因未开放而消失：报名关闭时仍可阅读赛事信息，项目与影像无数据时显示空态，成果未发布时显示待发布状态。按钮是否允许报名、投稿或上传仍由原业务状态控制。

这避免把可能重叠的作品提交和图片直播错误建模为严格串行流程，也保证跨赛事切换后布局不跳动。

### 3. URL 同时保存赛事与环节

规范 URL 为 `/hackathon?event=<eventKey>&view=<register|projects|media|showcase>`。外层根据模板把 `eventKey` 映射为 competition slug。媒体内部“最新/精选”使用 `mediaView`，避免与外层 `view` 冲突；项目详情和投稿继续使用现有 `id`、`create`、`submit` 参数。

初次进入没有合法 `view` 时按赛事状态选择：未来或报名中进入 `register`，进行中优先进入 `projects` 或 `media`，已结束且成果可见进入 `showcase`。用户明确切换赛事时保留当前环节；若内容暂不可用，显示该环节空态而不自动跳走。

旧的 `/hackathon/showcase`、`/hackathon/works`、`/projects?competition=...` 和 `/media?event=...` 继续解析，并转换到相同赛事上下文或保留独立兼容页。

### 4. 工作区壳稳定，内容保留各自滚动模型

桌面赛事目录和环节栏使用 sticky，而不是 fixed 浮层；外层不再监听正文滚动来隐藏导航。报名页原有内部整屏滚动保留，但嵌入时高度扣除全局导航和工作区标题；项目、影像和成果使用文档滚动，禁止再增加一层纵向滚动容器。

当前赛事身份、状态和日期位于环节栏上方或同一标题带中，不另造第三条横向 Tab。左侧赛事卡只显示届次/标题、日期和状态，不使用大海报，避免挤压图片瀑布流和项目网格。

### 5. 全局导航区分内容栏目与行动入口

桌面主导航只保留活动集合、AI 社区、浙客松和生态介绍。下载 App 从 `navLinks` 移到右侧 utility 区，与搜索和个人入口相邻，使用独立按钮样式。项目广场和影像库不再作为一级栏目，但独立路由、搜索结果、分享链接和旧收藏入口继续有效。

移动底栏保留高频内容与个人入口，浙客松取代项目广场成为一级入口；生态介绍和下载 App 留在“更多”面板。

### 6. 响应式与可访问性

在 980px 以下，左侧赛事目录收为工作区标题中的赛事选择按钮，点击后打开 body-level 抽屉；四环节栏保持单行横向滚动并显示当前项。所有赛事卡和环节项使用原生 button/link、`aria-current`、`aria-selected` 和可见焦点，状态同时使用文字而不是仅靠颜色。切换赛事或环节后焦点与页面标题保持可理解，`prefers-reduced-motion` 下取消平滑滚动。

### 7. 外层只编排，不重写子页面视觉

跨届赛事目录与四环节栏使用站点级设计语言；项目广场和赛事影像进入嵌入模式后只移除重复赛事选择器，继续保留各自已经确认的背景、色彩、卡片和影像布局。外层通过留白分隔控制区与正文，不给子页面强制覆盖主题 token，也不显示 `EVENT`、阶段名等装饰性重复文字。

### 8. 四环节栏是轻量导航，不是四张功能卡

赛事标题、状态和日期压缩为单行上下文；四个环节仅保留小图标、名称和当前项下划线。移除环节编号、说明文字、整块选中背景、图标方框与纵向分隔线，使导航承担定位而不是内容展示。移动端使用同一轻量表达并允许横向浏览，不恢复第二套卡片式导航。

## Risks / Trade-offs

- [现有报名页使用 `100svh` 内部滚动，嵌入后可能与工作区 sticky 区域冲突] → 通过明确的工作区高度变量调整报名根节点和页内锚点偏移，并分别验收桌面和移动端。
- [项目与影像组件依赖各自 URL 参数] → 增加受控 props，独立模式保持原参数读取；嵌入模式由外层传值并使用命名空间参数。
- [左栏压缩项目网格和瀑布流] → 桌面宽度控制在 252px，内容区使用 `minmax(0,1fr)`；980px 以下移除侧栏。
- [历史深链和分享二维码仍指向独立路由] → 保留兼容路由，不批量重写已生成链接；新增工作区内链接优先使用规范 URL。
- [四个环节一直可见可能让未开放内容显得可点击] → 页面保留可进入的说明型空态，真正写操作单独禁用并解释原因，不把整个栏目做成消失或死按钮。

## Migration Plan

1. 先补充路由解析测试，覆盖四环节、非法参数、competition 兼容和浏览器恢复。
2. 增加项目与影像嵌入模式，保持独立路由输出不变。
3. 替换 `HackathonSeasonOne` 外层布局并接入四环节。
4. 收口桌面与移动导航，维护中英文文案。
5. 运行相关单测、lint、构建、OpenSpec 校验和桌面/移动真实浏览器流程。
6. 若出现阻断性回归，恢复旧 `HackathonSeasonOne` 组合和导航项；子组件新增 props 为可选，不影响原独立页面。

## Open Questions

- 当前模板只配置报名页与成果页可见性，本次先让四个环节稳定存在；未来若运营需要单独控制项目或影像开放时间，应扩展正式模板字段，而不是在前端用日期猜测隐藏栏目。
