## Context

活动集合是主站高频信息发现页面，当前同时存在直角全局类、文字底线 Tab、局部大圆角、透明背景、渐变氛围和多套强调色。筛选、社团、结果统计、视图切换与活动卡片都能工作，但缺少统一表面层级；特别是无外框切换器和透明按钮容易与背景混在一起。

About 与黑客松报名介绍已经形成稳定的直角结构叙事语言，黑客松成果和赛事营销正在形成海报语言。本次不把两者混进主站，而是让活动集合验证第三种“精致操作型”语言。它强调比例、对比、材质和交互连续性，不把圆角或直角本身当作教条。

## Goals / Non-Goals

**Goals:**

- 建立活动集合可独立验收、可逐步推广的精致主站表面基线。
- 让筛选、社团、结果统计、卡片/列表切换和活动内容具有稳定边界与清晰阅读顺序。
- 同时适配白天/夜间与桌面/移动，不牺牲键盘、触控、reduced-motion 和现有功能。
- 保留活动标题、日期、地点、类别、状态、组织归属和操作入口的正式内容优先级。

**Non-Goals:**

- 不重做活动 API、筛选状态、排序逻辑、推荐助手、上传或详情功能。
- 不把活动页改成营销落地页，不增加虚构指标、装饰性英文或无内容价值的视觉模块。
- 不修改 About、黑客松报名、赛事成果海报、AI 社区、项目广场或后台。
- 不在试点完成前把新类名和 token 批量推广到全站。

## Decisions

### 1. 精致感来自层级与对比，不来自固定几何教条

活动页使用微圆角而非全胶囊或全硬边：内容卡片控制在中等圆角，工具与切换控件使用更小圆角，状态点和头像保留语义圆形。所有可点击控件必须通过边框、表面、文字或焦点环与背景区分；视图切换可以保留底线选中语法，但整组必须通过外边界与中性表面建立操作区域。

相比继续套用全站 `rect-*` 类，这能避免把 About 的结构叙事语言误当作高频产品控件；相比全面大圆角化，又能保留主站的克制和清晰。

### 2. 保留页面原背景，只给必要对象建立表面

页面画布继续继承站点原有背景、动态壁纸和局部氛围光，不新增整页蓝黑铺色。只有分类切换、学院与排序控件、社团筛选、视图切换和真实活动条目建立必要表面。普通卡片不使用毛玻璃；白天以暖白和石墨文本为主，夜间工具与卡片使用中性蓝黑而非青绿，强调色统一为低饱和蓝紫。

每个对象只使用边框或阴影中的一个主要深度信号。工具不得为了分组再套一层无任务意义的大容器；卡片默认靠细边框与实体表面站稳，悬停时才增加轻微位移和柔和阴影。

### 3. 视图切换使用有边界的轻量 Tab 控件

“卡片 / 列表”保留图标、文字和蓝色底线，但整组放入一个有细边框、独立中性底色和有限内间距的容器。当前项通过蓝色横条、更高文字对比和 `aria-pressed` 共同表达，非当前项仍保持可读；键盘焦点不依赖颜色，触控尺寸至少 40px。

不回到与背景混在一起的无框 Tab，也不把两个选项做成厚重的实体分段按钮或大胶囊。外层容器可以微圆角，内部选项保持轻薄。

### 4. 筛选、社团与结果工具合成连续工作区

桌面标题区保持简洁；分类、学院、排序、社团和结果/视图切换通过相邻但不嵌套的必要边界组织，不增加包住全部筛选器的外层大壳。分类与社团项使用明确选中面，避免每个按钮都成为独立厚重卡片。移动端保留当前顶部分类、排序、AI 和学院入口，不机械压入桌面工具壳。

### 5. 活动条目由真实内容建立可观性

桌面卡片继续以真实活动图片为首要视觉，正文只保留类别/状态、标题、时间和地点等决策信息；边框和实体底色提供对比，不添加装饰性 glow。列表行保持更高信息密度。移动卡片维持当前紧凑结构，统一边框、背景和按压反馈。

### 6. 作用域隔离后再推广

新增样式全部挂在活动页根作用域或活动专用类下，不重写通用 `rect-*`、导航、About 或黑客松 token。试点通过后，再把实际存活的 token 提取为主站设计系统；本次不先制造全局抽象。

### 7. 可访问性和性能沿用现有能力

保留原生 button、`aria-pressed`、`role=group`、可见焦点和 reduced-motion。视觉调整不新增依赖，不增加持续动画、背景 canvas 或高成本 blur；卡片图片继续使用 `SmartImage` 和懒加载。

## Risks / Trade-offs

- [活动页仍引用部分全局 `rect-*` 类，局部可能残留旧视觉] → 只替换试点主路径上的控制与表面，浏览器验收后逐项清理，不全局重定义旧类。
- [工具表面增加边界后可能显得厚重] → 使用低对比度边框、单层背景和有限内边距，禁止工具壳内再嵌套装饰卡片。
- [白天和夜间的对比强度不一致] → 分别检查背景、边框、正文、次要文字、选中态和焦点，而不是只检查颜色 token 是否存在。
- [一次试点被误当作全站完成] → 在规格和产品状态中明确本次只覆盖活动集合，后续推广必须单独确认。

## Migration Plan

1. 建立作用域 token 和活动页视觉合同。
2. 先调整页面画布、标题、筛选、社团和视图切换，再统一卡片与列表行。
3. 在真实浏览器检查桌面/移动和白天/夜间，修正对比、溢出、密度与交互。
4. 通过 lint、构建、资源检查和严格 OpenSpec 校验后推送。
5. 如试点不成立，回退活动页专用提交即可；数据、API、About 与黑客松不受影响。

## Open Questions

- 精致风推广到 AI 社区、项目广场和影像库时，应复用哪些试点 token、哪些只属于活动信息发现，待本次浏览器验收后再决定。
