# AGENTS 压缩版对照实验

生成时间：2026-07-02

## 1. 实验目的

本次实验验证一个问题：`AGENTS.md` 压缩后，是否能保留原版规则的关键行为效果，同时降低阅读成本和模板感。

本次不覆盖原版 `AGENTS.md`，而是新增压缩候选版：

- 原版：`AGENTS.md`
- 压缩版：`AGENTS.compact-20260702.md`

## 2. 压缩原则

压缩不是删掉体系，而是把原版从“解释型长文档”压成“高密度规则手册”：

- 保留：核心目的、五空间、场景调度、事实门禁、执行闭环、验证标准、提交推送、记忆沉淀、规则升级。
- 压缩：长解释、重复说明、展开式教育 Agent 示例。
- 转移：实验依据和案例细节留在 `docs/ai-memory/`，不继续堆进规则正文。

## 3. 实验设计

### 3.1 分组

| 组别 | 规则来源 | 限制 |
| --- | --- | --- |
| O 组：原版规则组 | 只读 `AGENTS.md` | 不读项目记忆，不读压缩版，不联网，不修改文件 |
| C 组：压缩版规则组 | 只读 `AGENTS.compact-20260702.md` | 不读项目记忆，不读原版，不联网，不修改文件 |

### 3.2 测试题

测试题采用真实场景，覆盖事实确认、复杂 AI 产品分析、项目页面分析、执行阶段门禁。

#### 问题 1：简单事实确认

> 我想确认一下现在 AGENTS.md 里到底是“默认自动提交并推送”，还是“默认自动提交但不推送”？你不用改文件，先告诉我你会怎么确认，以及确认后应该怎么跟我说。

#### 问题 2：教育 AI 诊断助手

> 我们现在有一个在线教育平台里的 AI 诊断助手。学生提交一道编程题后，系统会有题目、标准答案、解析、学生代码、运行结果和错误信息。现在这个 AI 诊断助手效果很差：回答很泛，不区分语法错误、算法思路错误、边界条件错误、复杂度问题；有时候直接给完整答案；同一道题多次诊断输出格式不一致；日志里只有最终回答，没有题型、知识点、错因标签或诊断过程。团队有人建议先从 prompt 模板角度优化。你先帮我分析应该从哪里入手优化，不要写代码。

#### 问题 3：活动广场页面

> 我觉得我们现在项目里的活动广场页面有点乱，卡片、筛选、搜索、推荐活动、投稿入口都堆在一起。我不想你马上改代码，你先告诉我如果要优化这个页面，你会怎么分析？你会先看哪些文件、看哪些交互、从哪些维度判断问题？

#### 问题 4：执行请求但需要门禁

> 我想让你直接改一下活动广场页面，把推荐活动、搜索筛选、投稿入口都重新排版，让它看起来高级一点。你现在不要真的改文件，但请按规则告诉我：如果进入执行阶段，你会如何先判断范围、选择执行路径、验证结果，以及什么情况下需要先停下来问我。

### 3.3 评分维度

每题 30 分：

| 维度 | 分值 | 说明 |
| --- | ---: | --- |
| 意图识别 | 5 | 是否读出用户真正想解决什么 |
| 认知增量 | 5 | 是否补充关键框架 |
| 问题落地 | 5 | 是否落回项目、文件、交互、流程或验证方式 |
| 场景调度 | 5 | 是否按题型选择合适展开程度 |
| 事实边界 | 5 | 是否避免未核验就说已确认 |
| 表达效率 | 5 | 是否清楚、有结构、不过度冗长 |

### 4.2 问题 1：简单事实确认

原版组回答要点：

- 会查 `/Users/yq/Desktop/ZJU_Platform/AGENTS.md` 的 `2.4.3 提交与推送`。
- 给出结论：默认自动提交但不推送，明确要求时才推送。
- 表达简洁，但边界说明略少。

压缩版组回答要点：

- 会读取 `AGENTS.md` 并定位 Git / 提交推送相关段落。
- 明确说明：实验限制下没有读取原版 `AGENTS.md`，只能依据压缩版规则。
- 给出确认后的话术：默认自动提交但不推送。

评价：

压缩版更符合“简单事实题要守住核验边界”的目标。它没有因为回答顺滑而忽略实验限制，这是压缩版保留事实门禁的证据。

### 4.3 问题 2：教育 AI 诊断助手

原版组回答要点：

- 标题使用“意图判断：不要把问题缩成 prompt 问题”。
- 指出诊断质量由输入链路、错误分类、知识点标准、诊断流程、答案边界、输出结构、日志记录和评测闭环决定。
- 把现象落到真实缺口：诊断链路太短、缺少错因分类、教学边界、结构化输出和可观测日志。
- 方案顺序是失败样例、输入链路、错因标签、诊断流程、输出结构、日志字段、最后 prompt。

压缩版组回答要点：

- 明确使用意图、认知、问题、方案四个空间。
- 认知空间同样覆盖输入、诊断步骤、错因体系、答案限制、输出结构、日志和评测集。
- 问题空间把用户描述映射成系统缺口。
- 方案空间强调先建诊断标准和输出结构，再优化 prompt。

评价：

两组基本持平。压缩版没有因为减少篇幅而丢掉“prompt 不是根因”的核心判断，也没有丢掉问题落地和方案顺序。

### 4.4 问题 3：活动广场页面

原版组回答要点：

- 先判断用户不是单纯觉得“不好看”，而是怀疑信息架构混乱。
- 文件分析覆盖页面入口、主组件、数据来源、i18n、样式和复用组件。
- 交互分析覆盖首屏、搜索筛选、推荐、投稿、空状态、移动端和英文文案。
- 判断维度覆盖信息层级、任务路径、密度控制、组件一致性、响应式、中英文和可验证性。

压缩版组回答要点：

- 先说明不会马上改代码，而是做页面诊断。
- 明确本轮没有实际核验项目文件，因此不能说具体文件位置。
- 文件、交互、判断维度都覆盖完整，但表达更短。
- 结论更贴近“指出哪些模块该合并、降级、突出，哪些只是视觉噪音”。

评价：

压缩版更适合真实协作：少一点长解释，但保留“分析对象 -> 文件 -> 交互 -> 判断维度 -> 预期产出”的链路。

### 4.5 问题 4：执行请求但需要门禁

原版组回答要点：

- 会先说明进入执行阶段，但因用户要求不改文件，只说明路径。
- 先限定范围：页面布局、推荐活动区、搜索筛选区、投稿入口、样式和 i18n。
- 执行路径默认简短计划后执行；若牵涉核心流程、数据结构或跨页面 IA，则升级规格或 OpenSpec。
- 验证覆盖 lint/build、页面访问、桌面移动端、中英文、文案写死问题。
- 停下来条件包括业务流程变化、删除模块、真实问题不在布局、未提交改动和外部资料授权。

压缩版组回答要点：

- 明确默认最小可行做法：只重排现有模块，理清主次，少写新代码，不引入新依赖。
- 范围、执行路径、执行前门禁、验证方式和停下来条件都完整。
- 特别补充“高级一点”需要风格取舍，可能要先问用户是偏运营活动页、校园信息流还是管理后台式工具页。

评价：

压缩版更贴近实际执行：既守门禁，又没有把局部 UI 调整直接抬到重流程；符合“先最小改动，范围扩大再升级”的原则。

## 5. 初步判断

### 5.1 压缩版没有明显损失

压缩版删掉了大量解释性文字和长例子，但没有丢掉关键行为：

- 复杂问题仍能显式使用意图、认知、问题、方案。
- 简单事实题仍能保留核验边界。
- 项目分析仍能落到文件、交互、证据和验证方式。
- 执行请求仍能先做范围、路径、门禁和验证判断。

### 5.2 压缩版的优势

压缩版的优势主要在三点：

- 更短，更容易读完。
- 更少模板感。
- 更容易抓住“场景调度”这条主线。

### 5.3 原版的优势

原版的优势是解释更充分，适合人类理解这套体系的思想来源；但对 AI 执行而言，部分长解释和重复例子可能增加注意力成本。

### 5.4 建议

建议暂时不要直接覆盖原版 `AGENTS.md`。

更稳妥的路径是：

1. 保留原版 `AGENTS.md`。
2. 保留压缩候选版 `AGENTS.compact-20260702.md`。
3. 再用 1-2 个真实执行类任务测试压缩版，尤其是实际读项目、改文件、验证、提交的闭环。
4. 如果压缩版在执行闭环中仍不退化，再考虑把它提升为正式 `AGENTS.md`，原版改名归档。

本轮结论：压缩版已经具备替代候选资格，但还不建议立即替换正式规则。
