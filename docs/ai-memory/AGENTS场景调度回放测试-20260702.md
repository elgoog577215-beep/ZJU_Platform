# AGENTS 场景调度回放测试

生成时间：2026-07-02

## 1. 测试目的

本次测试只验证 2026-07-02 对 `AGENTS.md` 的小重构是否解决两个已知问题：

- 简单事实确认题：裁剪表达后不能凭摘要或记忆说“已确认”。
- 复杂项目分析题：不能只列清单，要体现意图、认知、问题落地和方案产出。

这不是重新跑完整 A/B/C 实验，而是一次规则回放测试：用之前报告中最有代表性的失败点，看新规则是否给出了明确约束。

## 2. 测试一：提交与推送事实确认

### 2.1 测试问题

> 我想确认一下现在 AGENTS.md 里到底是“默认自动提交并推送”，还是“默认自动提交但不推送”？你不用改文件，先告诉我你会怎么确认，以及确认后应该怎么跟我说。

### 2.2 旧问题

旧版裁剪表达容易出现这种问题：

- 回答很顺。
- 但没有读取原文时，也可能说“当前结论已经指向默认自动提交但不推送”。
- 这会把摘要、记忆或推断误说成当前事实。

### 2.3 新规则约束

本次新增或强化的规则要求：

- 简单事实确认应直接回答结论、依据或核验路径。
- 尚未读取原文、运行命令、打开页面或核验资料时，只能说“我会如何确认”或“基于当前信息的初步判断”。
- 裁剪只能裁剪表达篇幅，不能裁剪事实核验、依据说明和不确定性边界。
- 未读取、未运行、未打开或未核验时，不得把推断说成已经确认的事实。

### 2.4 按新规则应给出的回复形态

```markdown
我会先读取当前项目根目录的 `AGENTS.md`，定位 `2.4.3 提交与推送`，再全文搜索是否有冲突表述，例如“默认推送”“自动推送”“用户明确要求推送”。

在未读取原文前，我只能说明确认方法，不能说已经确认。

确认后如果原文仍是现行规则，我会这样跟你说：

当前 `AGENTS.md` 写的是：默认在任务达到收束条件后自动提交但不推送；只有你明确要求推送时才推送。所以默认行为是提交，不自动推送。
```

### 2.5 评价

有效。

新规则把事实题的行为从“顺滑回答”拉回“证据优先”。它不会强迫输出意图/认知/问题/方案标题，而是要求先说明核验路径和不确定性边界。

## 3. 测试二：活动广场页面混乱但暂不改代码

### 3.1 测试问题

> 我觉得我们现在项目里的活动广场页面有点乱，卡片、筛选、搜索、推荐活动、投稿入口都堆在一起。我不想你马上改代码，你先告诉我如果要优化这个页面，你会怎么分析？你会先看哪些文件、看哪些交互、从哪些维度判断问题？

### 3.2 旧问题

普通回答容易只列：

- 看哪些文件。
- 看哪些交互。
- 从哪些维度分析。

清单本身有用，但容易缺少一个上游判断：这个页面到底承担什么主任务，为什么会乱。

### 3.3 新规则约束

本次新增或强化的规则要求：

- 项目分析但暂不执行时，先说明分析对象和判断维度。
- 再说明会读取哪些文件、检查哪些交互、寻找哪些证据。
- 最后说明预期会产出什么诊断或方案。
- 复杂问题显式输出空间标题时，标题应尽量写成“空间名 + 本轮关键判断”。
- 问题空间要把认知维度落回当前项目、文件、模块、数据、交互、流程或验证方式。

### 3.4 按新规则应给出的回复形态

```markdown
**意图判断：先确认页面主任务，而不是先挪 UI**

你说的“乱”大概率不是单个卡片样式问题，而是活动广场同时承担浏览、搜索、筛选、推荐和投稿入口，主次没有分清。

**认知维度：用信息架构、任务流和视觉优先级分析**

我会判断哪些是主任务，哪些是辅助任务，哪些是运营入口；再看用户进入页面后第一步做什么，哪些模块在抢注意力。

**问题落地：先看文件、交互和证据**

我会先看页面入口、活动卡片、搜索筛选、推荐活动、投稿入口、数据状态、响应式样式和中英文文案。交互上检查首屏、搜索、筛选、推荐点击、投稿入口、空状态、移动端和英文长文案。

**方案产出：先给诊断，再决定是否改代码**

最后产出页面诊断：哪些模块是主任务，哪些应降级或分流，混乱来自信息层级、视觉密度、交互状态还是响应式问题，以及最小改动路径。
```

### 3.5 评价

有效。

新规则把回答从“文件和交互清单”推进到“主任务判断 -> 分析维度 -> 项目证据 -> 诊断产出”。这符合用户想要的项目分析方式，也避免马上进入代码修改。

## 4. 总结

本次小重构的效果是明确的：

- 对事实题：新增规则能阻止“未核验但说已确认”的问题。
- 对复杂项目题：新增规则能促使回答带着判断组织文件、交互和证据，而不是只列清单。
- 对表达：新增“空间名 + 本轮关键判断”能减少模板感，同时保留空间机制。

局限：

- 本次是规则回放测试，不是重新跑多 subagent blind test。
- 它能证明新规则覆盖了报告中暴露的关键失败点，但不能证明所有未来回答都会稳定遵守。
