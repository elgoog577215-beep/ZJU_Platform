# 结构化活动导入

适用于已经核对标题、简介、正文和来源的活动资料，例如 WorkBuddy 本地导出后整理的公众号内容。直接提交现成字段；不需要操作网页、抓取原文或重新调用 AI 提取。

## 前置条件

- 平台地址：`https://tuotuzju.com`。
- 使用现有登录接口取得 Bearer token；不要把凭据写进 JSON 文件或日志。
- 每次提交一篇活动及其封面。批量客户端逐篇保存返回的 ID 和状态。
- 缺少证据的日期、二课分、志愿时长传 `null` 或省略，不用发布日期代替活动日期。

## 接口与字段

`POST /api/events/import`，请求头 `Authorization: Bearer <token>`。

两种请求格式任选一种：

1. `multipart/form-data`：文本字段 `payload` 为活动 JSON，文件字段 `cover` 为本地 JPEG、PNG、WebP 或 GIF，最大 10 MiB。客户端自动生成 multipart boundary。
2. `application/json`：直接传活动对象，`image` 引用已上传的 `/uploads/images/...` 图片；不下载远程图片。不能同时提交 `cover` 和 `image`。

| 字段                                               | 要求                                                                             |
| -------------------------------------------------- | -------------------------------------------------------------------------------- |
| `title`                                            | 必填文本，最长 500 字符                                                          |
| `description`                                      | 必填简介，最长 5000 字符                                                         |
| `link`                                             | 必填 HTTP(S) 原始来源，用于去重；不能携带账号密码                                |
| `content`                                          | 已整理正文，最长 200000 字符                                                     |
| `date`、`end_date`                                 | ISO 日期或时间，例如 `2026-10-01`、`2026-10-01T14:00:00+08:00`；结束不能早于开始 |
| `category`、`location`、`organizer`、`tags`        | 现有活动字段，字符串；标签沿用逗号分隔格式                                       |
| `target_audience`、`source_college`、`notice_type` | 已确认的受众、学院与通知类型文本                                                 |
| `score`、`volunteer_time`                          | 有来源证据的文本；不明确则省略或 `null`                                          |
| `is_college_notice`                                | 布尔值，也接受 `0`、`1`                                                          |
| `publisher_profile_id`、`organizer_profile_id`     | 可选正整数，必须通过现有主体权限检查                                             |
| `status`                                           | 默认 `pending`；可传 `draft`、`pending`、`approved`，最终状态服从现有审核权限    |
| `image`                                            | 仅 JSON 方式填写已经存在的站内图片路径                                           |

未知字段会返回 400，避免把本地批次状态或账号字段误写入活动。普通用户请求 `approved` 仍进入待审核；有既有审核豁免权限的主体可明确指定 `approved`。

## 一次提交 JSON 与封面

保存为 `import-event.mjs`，使用 Node.js 22 或更高版本。`event.json` 只包含上表中的业务字段；本地路径作为单独参数传入。

```js
import fs from "node:fs/promises";
import { basename } from "node:path";

const [jsonPath, coverPath, mime = "image/jpeg"] = process.argv.slice(2);
if (!jsonPath || !coverPath || !process.env.ZJU_TOKEN) {
    throw new Error("需要 JSON 路径、封面路径及 ZJU_TOKEN 环境变量");
}
const payload = JSON.parse(await fs.readFile(jsonPath, "utf8"));
const form = new FormData();
form.append("payload", JSON.stringify(payload));
form.append("cover", new Blob([await fs.readFile(coverPath)], { type: mime }), basename(coverPath));
const response = await fetch("https://tuotuzju.com/api/events/import", {
    method: "POST",
    headers: { Authorization: `Bearer ${process.env.ZJU_TOKEN}` },
    body: form,
    redirect: "error",
});
const result = await response.json();
console.log(JSON.stringify({ httpStatus: response.status, ...result }, null, 2));
if (!response.ok && response.status !== 409) process.exitCode = 1;
```

设置会话内的 `ZJU_TOKEN` 后执行：

```powershell
node import-event.mjs event.json cover.jpg image/jpeg
```

## 回执、验收与恢复

- 成功为 HTTP 200，返回保存的活动对象，至少包含 `id`、`status` 和 `image`。待审核与草稿不能据此宣称已公开。
- 来源重复为 HTTP 409，`error` 是 `RESOURCE_DUPLICATE_SOURCE`，同时返回 `existing_id` 和 `existing_title`。记录已有 ID 并回读核对，不能通过更换来源链接规避去重。
- 参数错误 400、未登录 401、主体无权限 403、封面过大 413、不支持的请求格式 415；修正原因后再提交。
- 超时、断网或 500 可能发生在活动写入之后：先按来源对账，不自动重发或退回旧上传接口。相同来源通过此入口在单个服务进程内串行处理；这不是跨进程事务保证。
- 封面在来源、主体检查后才写盘；活动 INSERT 失败清理本次封面，写入后发生错误则保留文件。复用已有 `image` 不删除原文件。
- 入库后仍沿用既有搜索索引、AI 治理建议和通知流程；这些后台流程不重新覆盖本次提交的正式正文，也不自动批准待审核内容。

验收时回读对应活动，检查标题、简介、正文、封面路径和实际审核状态；封面 URL 应返回图片。公开结果通过活动页 `https://tuotuzju.com/events?id=<id>` 查看。
