本文定义已确认的产品设计，开发据此实现并验证。设计可以包含尚未实现的部分；现实差距与验收范围统一见[产品状态](产品状态.md)，代码存在不等于生产可用。

```text
产品蓝图
├── 产品定位
├── 内容设计：业务对象、组成、含义与关系
├── 逻辑设计：产生、使用、变化与协作
├── 交互设计：页面职责、操作、状态与反馈

```

两份功能设计属于这份蓝图的组成部分；全站规则在本文维护，业务细节不重复复制。操作步骤见[手册](操作手册/)，安装和运行见 [README](../README.md)。

## 产品定位

拓途浙享是拓浙 AI 生态的数字底座与公共入口，连接校园机会、AI 学习、社区协作、实践项目、赛事、人才和组织身份。希望用户参与一次活动或比赛后，能够留下可信的关系与成果，继续进入下一次学习、合作和实践。

| 主体         | 分工                                                 |
| ------------ | ---------------------------------------------------- |
| 拓浙 AI 生态 | 校园、教育、实践和产业协作的整体网络                 |
| 拓途浙享     | 本仓库承载的数字平台，保存内容、身份、参与和成果关系 |
| 智能体协会   | 校内组织与校园协作                                   |
| 奇鹰科技     | 对外商业合同、交付、收款、合规和 IP                  |

公开品牌使用“拓浙 AI 生态”。合作主体与平台、协会、公司各自独立，不因出现在网站上就成为公司资产或下属组织。

主要用户为发现机会与学习的学生和青年开发者、组织活动的社团与学院、提出真实问题的合作方、维护内容与关系的运营者，以及浏览公开内容的访客。产品价值看能否促成并记录有效参与、成果与合作；长期效果需要实际数据证明。

范围不扩展为通用校园门户、独立教务系统、支付合同系统或另一套社交网络。原生端复用同一产品，不另建身份和业务体系。独立项目中心、网址开放广场、全站搜索入口及活动 AI 助手的开放情况见下文，不因保留底层数据而恢复入口。

## 内容设计

### 核心业务对象

| 对象           | 必须表达的内容                                                       | 关系边界                                                 |
| -------------- | -------------------------------------------------------------------- | -------------------------------------------------------- |
| 账号           | 登录方式、会话、账号状态与权限                                       | 账号不等于公开组织或个人主页                             |
| 公开主体       | 名称、介绍、头像、类型、成员与别名                                   | 一个人可参与多个组织；成员关系明确确认                   |
| 合作关系       | 合作主体、合作方向、展示范围、支持类别                               | 组织名录、公开 profile 和核心合作名录分开                |
| 活动           | 标题、介绍、实际时间、地点、面向对象、报名方式、来源、审核状态       | 上传者、发布主体、主办方、合作方可不同；未知事实保留为空 |
| 学习与社区内容 | 内容类型、正文或资源、作者、发布主体、标签、来源与审核状态           | 采集、网页、文档和 CLI 是输入方式，共用内容归属          |
| 长期项目       | 名称、问题、团队、进展、仓库和部署证据、所属主体                     | 可持续迭代，独立于某一次参赛                             |
| 赛事与参赛作品 | 当届信息、阶段、赛题、报名、提交快照、奖项、公开授权与精选状态       | 每届独立；作品与长期项目只有明确关联后才连接             |
| 媒体           | 图片、视频、音频或文章本体及作者、来源、授权、审核信息               | 可独立发布，也可关联赛事、活动或主体，不复制媒体本体     |
| 网址导航       | 分类、链接、双语名称、说明、用途关键词；账号自定义分组与排序         | 公共目录由白名单维护，个人编辑属于各自账号               |
| 抽奖           | 每期规则、奖品数量、四个时间、凭证要求、审核要求、报名编号与开奖结果 | 公开编号和奖项；凭证与领奖联系方式不公开                 |

浙客松的字段与对象关系见[内容设计](功能设计/浙客松.md#内容设计)；采集来源、原文、运行记录和候选的区别见[内容设计](功能设计/内容采集.md#内容设计)。

### 内容组织

- 生态介绍承载资源概览、业务与参与方式。业务口径为“社群与沙龙、浙客松、学习培养、项目实践”，项目实践包含“产业联培、自主立项”。
- AI 社区以新生资料库、期末资料库、AI 学习库和沙龙交流群组织入口。新生资料库连接“浙大校园信息站”ima；期末库承载课程资料；AI 学习库包括教程路径及 AI/其他配套资源。
- 沙龙是正式活动，使用讲座分类与“沙龙”标签；不以社区帖子另存同一场活动。旧讨论和内容深链保留各自兼容关系。
- 生态支持方以四类前台入口展示，底层支持类别与合作范围独立保存；浙客松合作区采用学院合作、产业合作、组织合作，不能混成一套分类。
- 公共 profile 目录只批量展示允许公开发现的组织。个人主页从精确链接、内容作者或用户中心进入，不能通过整理名录扩大个人信息公开范围。

## 逻辑设计

### 参与、归属和公开

用户从机会或内容进入报名、学习、投稿或实践，结果关联到明确的活动、赛事、项目和主体，再用于成果展示与后续协作。每一步保持原对象及其归属，不把一次活动转化成无来源的新帖子。

内容经输入、审核与授权后公开；网页、CLI、结构化导入和微信采集复用相同领域规则。免审核资格与后台管理权分开。历史归属修正需要证据、人工确认与审计，不按姓名、标题或仓库地址猜测。

赛事作品公开必须同时满足审核通过、作者同意公开、后台精选、当届成果已发布且记录未删除。精选排序不代表获奖排名。长期项目数据继续保留并受后台治理，独立项目中心及旧入口已撤下。完整链路见[浙客松逻辑设计](功能设计/浙客松.md#逻辑设计)。

媒体本体通过显式关系关联活动或赛事，精选与归档用途由关系表达；不以文件名、标签或上传时间猜测归属。分享卡、海报、搜索结果都是正式业务对象的展示，不拥有另一份事实。

### 发现活动与使用导航

活动列表按实际开始时间从新到旧，未知日期置后，同一时间保持稳定分页。筛选表达当前范围，报名方式与来源可追溯。搜索负责查询，活动推荐负责根据需求匹配机会，二者保持各自逻辑。前台全站搜索与活动 AI 助手目前暂停入口，底层服务保留；重新开放需要明确设计与验收。

首页公共网址目录人工维护，每类默认显示最多 9 项，原地展开/收起，搜索覆盖全部匹配结果。账号可以编辑独立分组、链接和排序，保存冲突保留草稿供处理；账号切换清除上一账号草稿。支持 HTML 书签导出与 JSON 备份恢复。

网址开放广场暂缓：不展示分享和切换入口，公开 API 关闭，既有数据保留。已有分享设计只在重新确认开放后使用：发布选定的已保存快照并审核，复制后各自独立，撤回原分享不删除他人的副本。

### 社区抽奖

1. 管理员编辑草稿，设置名称、介绍、规则、奖品及数量、凭证与人工审核开关，以及报名开始、报名结束、开奖、领奖截止四个严格递增时间。保存草稿后，在本期管理页面自动生成详情页专属链接和二维码，可复制链接、下载 PNG 插入公众号推文或海报；草稿提示发布后页面才公开，链接不指向列表或 API。发布后锁定配置；需要改变规则时说明原因取消原期，再建新期。
2. 用户登录后报名，每期每账号一个随机编号。不开放匿名、付费报名或多次抽取机会；公众号关注、点赞等不自动认定，启用凭证时按规则提交并审核。
3. 审核未通过可在报名截止前补交；报名结束后、开奖前仍可审核。仅开奖前已通过且账号未被禁用的报名进入抽取，同等概率，每人最多中奖一次。没有合格报名时公布空结果并结束。
4. 到点自动开奖并公示编号与奖项；中奖者在截止前填写私有领奖信息，管理员记录发放。页面访问不触发开奖，重启补处理不产生重复中奖或发放。

### 权限与治理

账号主体类型、审核资格、后台权限分别控制；组织账号不会自然取得管理员权限。开发管理员管理平台，普通管理员按明确运营能力使用同一套后台页面。账号隐私、报名、采集凭据、模型、系统、文件和数据库等敏感入口受开发管理员保护；抽奖管理同样只对平台管理员开放。

权限变更在后端验证操作者、目标、版本与审计，保留最后一个有效开发管理员，不允许通过普通资料编辑越权。页面能力随最新身份刷新，权限未知时不先展示业务内容。密码只能重置，不能查看原值。

### AI 参与业务

网站 AI 能力使用有来源的输入，输出建议、检索条件或候选，正式写入仍经过对应领域权限和审核。失败保留输入、最后有效内容与可恢复状态，不编造正式结果。AI 调用质量、真实 provider、权限和运行健康分别验证。

首页目前是目录关键词检索，RAG 的检索范围尚未确定；保留检索服务不构成实施 RAG 的决定。模型和索引技术边界见[搜索与 AI](#搜索与-ai)。

## 交互设计

### 全站框架与页面职责

全站共享导航、账号、语言、日夜主题和返回方式。一级入口承担业务选择，页内次级导航选择同一业务下的内容，不用多个侧栏重复表达层级。

| 页面       | 用户主要完成的事                       | 当前入口与约束                                                                             |
| ---------- | -------------------------------------- | ------------------------------------------------------------------------------------------ |
| 首页       | 搜索和使用网址，管理个人导航           | `/`；公共目录与个人编辑复用原站框架                                                        |
| 活动聚合   | 筛选活动，查看详情、来源与报名方式     | `/events`；AI 助手入口关闭                                                                 |
| AI 社区    | 选择学习专题或沙龙，浏览和提交相应内容 | `/ai-community`；选择后入口收为顶部，操作留在所属专题                                      |
| 浙客松     | 切换赛事，了解、参赛、看影像与成果     | `/hackathon/1` 等；四个二级 tab，无左侧赛事栏，详见[页面设计](功能设计/浙客松.md#交互设计) |
| 生态介绍   | 理解定位、资源、业务并选择参与方式     | `/about`；沿用已确认的首屏双栏、统计栏及四屏结构                                           |
| 公开主体   | 查看个人或组织及其公开内容、关系和成果 | `/u/:handle`、`/org/:handle`；组织名录 `/profiles`                                         |
| 媒体与文章 | 浏览对应类型的公开内容                 | `/media`、`/videos`、`/articles`；使用原对象的详情与分享                                   |
| 社区抽奖   | 了解规则、报名、查看编号/结果、领奖    | `/lotteries`、`/lotteries/:id`；同时适配公众号内访问与手机                                 |
| 运营后台   | 按权限管理内容、主体、赛事、采集和系统 | `/admin`；共用六域导航与业务组件，抽奖为 `?tab=lotteries`                                  |

手机宽度小于 `768px` 时隐藏生态介绍与浙客松入口，直接访问相应路由回到首页。这是当前开放范围；不能因旧文档要求移动适配而恢复入口。已开放的页面仍须做好窄屏、键盘、安全区和 WebView 操作。

独立项目中心和 `/future-learning` 公开页面已撤下；长期项目与历史登记数据保留。旧项目及旧赛事链接不恢复兼容。页脚鸣谢来自站点设置，未配置使用默认名单，明确设置为空则隐藏。

### 状态、视觉与操作

- 页面先表达当前对象和状态，再安排主要操作；空内容、待发布、无权限、加载失败不能显示成同一种空白。失败时保留草稿和可重试位置。
- 筛选、赛事选择和可分享的详情使用明确 URL；返回恢复合理范围。参数迁移须覆盖跳转与返回链，不能让 URL 已变而旧页面因退出动画滞留。
- 沿用已确认的品牌资产与布局，主题、字阶、间距和动效使用共享设计；整齐的网格和清楚层级优先。具体页面调整需真实视觉检查，不从旧截图推翻现行设计。
- 登录允许选择保持会话，所有入口使用同一存储规则。账号变化、退出、保存成功和保存冲突反馈明确，异步旧请求不能恢复已退出身份。
- 复制、分享失败提供手动文本等可操作降级。弹层支持键盘焦点、关闭与返回，避免遮挡底栏，不只通过提高 `z-index` 解决布局。
- 中英文表达同等信息；状态不能只靠颜色。尊重 `prefers-reduced-motion`，不同端保持相同业务入口，平台能力在运行时分流。

## 技术设计

### 代码与状态归属

```text
React / Web / PWA / 原生壳
  → 客户端 API → Express route → controller → 领域 service → SQLite / 存储
                              ↘ AI runtime、采集任务与平台桥接
```

| 位置                                                                                                  | 承载职责                                                     |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| [src/App.jsx](../src/App.jsx)                                                                         | Router、Provider、全局壳、路由懒加载、动态资源恢复与多端判断 |
| [src/features/](../src/features/)                                                                     | 按业务组织功能；遗留组件触及时逐步收口，不为目录美观整体搬迁 |
| [src/services/api.js](../src/services/api.js)、[platformClient.js](../src/services/platformClient.js) | 认证头、领域请求、错误与有限重试                             |
| [server/index.js](../server/index.js)、[API 路由](../server/src/routes/api.js)                        | 安全与接入中间件、路由、上传、SPA 与健康检查                 |
| [server/src/services/](../server/src/services/)                                                       | 领域服务、AI、采集、主体关系及多端能力                       |
| [server/src/config/](../server/src/config/)                                                           | 数据库、核心 schema、正式 migration                          |
| [shared/](../shared/)                                                                                 | 前后端共享的枚举、赛事路由和默认配置                         |

`AuthContext` 管会话，`SettingsContext` 管主题及设置，`MusicContext` 管跨页面播放；服务端数据通过客户端与领域 hooks 读取，组件本地状态只承载交互和草稿。目标分层不代表旧 controller 已全部拆完，遗留 SQL/业务混杂记入状态，新增代码不扩大它。

### 数据、配置与迁移

| 业务           | 正式存储与实现入口                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| 账号、公开主体 | `users`；`profiles`、`profile_members`、`profile_aliases`                                                         |
| 权限           | `account_type`、`review_permission`、`role/admin_scope`、`admin_permissions` 与会话/权限版本                      |
| 合作           | `ecosystem_partners.partner_scope`、`support_category`；独立于 profile 类别                                       |
| 活动、社区     | `events`；`articles`、`news`、`community_posts` 的既有兼容合同                                                    |
| 长期项目       | `project_cards`，显式发起人/主体关系，独立仓库与部署地址                                                          |
| 赛事           | 当届配置、报名、`competitions`、`competition_works` 与媒体关系，详见[浙客松技术设计](功能设计/浙客松.md#技术设计) |
| 账号网址导航   | `user_navigation_workspaces`；公开目录由 `src/features/navigation/` 的白名单与双语数据维护                        |
| 抽奖           | `lotteries`、`lottery_entries`、`lottery_winners`、`lottery_audit`                                                |
| 搜索与 AI      | 公开业务对象和 `resource_search_index`；Agent registry、模型配置、评测与遥测                                      |

SQLite 由 `ensureCoreSchema.js` 与 `runMigrations.js`、正式 migrations 共同维护。新变更提供可重复执行的迁移，启动失败明确暴露；`seed.js` 不代表生产 schema。运行数据库、WAL、上传、缓存和备份留在私有运行环境。

社区暂时兼容多表，但新输入不增加独立内容池。删除前台入口不默认删除历史数据；数据迁移需要核验引用、权限、备份和恢复。恢复数据库前停止服务并保全当前数据库及 WAL/SHM；优先前向修复，必须回退时配对数据库快照和应用版本，保全快照后的新增数据，不能直接覆盖。

导航保存带版本，冲突返回 `409` 并保留草稿，账号响应使用 `no-store`。分组最多 40、每组 100、总计 600 链接；仅接受无凭据的 HTTP(S) 地址。JSON 恢复先校验再进入草稿，旧快捷方式迁移不丢数据。公开分享 API `/api/navigation/collections` 当前返回 `404`，已有快照保留。

### 认证、安全与后台

JWT 沿用 7 天有效期；前台登录默认勾选保持登录，管理登录默认不勾选，最终遵循用户选择。所有入口共用 `authTokenStorage`：持久会话用 `localStorage`，临时会话用 `sessionStorage`。只有 `401/403` 清理失效会话，网络故障保留凭据并在恢复联网或聚焦时重试；退出及持久会话变更跨标签同步。

开发管理员使用 `role=admin/admin_scope=platform`，普通管理员使用 `role=operator/admin_scope=operations` 和明确模块能力。后端每次从数据库验证身份和权限，数据库故障返回 `503`，不用 JWT 旧权限兜底；`auth_version` 控制失效。`/api/admin/capabilities` 返回能力，`/api/admin/access` 的管理只对开发管理员开放，权限更新校验 `admin_access_version` 并与审计同事务提交。

权限未知时前端不挂载业务模块，能力按 15 秒及聚焦刷新。`/settings` 对普通管理员只允许页面字段白名单，发布主体列表按内容能力收敛。旧共用密码 `/auth/admin-login` 返回 `410`。已验证会话的管理员可豁免通用频次限制，仍须通过模块权限；登录失败次数独立计数。

上传在后端验证大小、类型和内容，HTML/SVG 等主动内容按隔离或下载方式提供；文件路径同时检查片段与 realpath，避免符号链接越界。采集出站限制受信域名、协议、端口及重定向，详见[采集技术设计](功能设计/内容采集.md#技术设计)。密码、凭据、私有 provider 地址、模型推理、用户隐私及私有材料不进入公开接口、日志或前端包。

### 搜索与 AI

`unifiedAiRuntimeService` 承载调用、结构化解析、修复和遥测；`aiAgentRegistryService` 记录能力和检查入口；`aiModelConfigService` 统一配置、测试及最终请求政策。

`general`、`fast`、`reasoning` 及维护脚本只使用私有登记 `a800-qwen` 的精确模型 `qwen3.8-27b`。后台写入、历史配置选择、配置测试、最终执行共用校验，缺少私有配置就明确不可用；魔搭、DeepSeek 或其他公网 provider 不作主路、备用或默认值。embedding 使用另行授权的自建模型。

`globalSearchService` 合并业务召回与索引补充召回，`resource_search_index.vector_json` 是轻量词元表示，不是真实 embedding。活动推荐按意图、召回、排序、解释与遥测分层。真实用户路径、provider 请求与返回模型是 AI 验收证据，配置列表、Mock、golden 或健康接口只说明各自覆盖范围。

### 抽奖运行

`migrations/lotteries.js` 经核心建表及正式启动迁移幂等执行。`/api/lotteries` 提供公开查询、登录报名与领奖；`/api/lotteries/admin` 只对平台管理员开放，不因其他运营权限放行。每期每账号唯一约束防止重复报名。

凭证限 5 MB 并校验解码像素，转 WebP 存私有 BLOB，只允许本人和平台管理员读取。四个时间以 UTC 毫秒保存、浏览器时区显示，服务器判定状态。独立 SQLite 连接使用 `BEGIN IMMEDIATE`，在一次事务中冻结合格名单、以 `crypto.randomInt` 无放回抽取、保存结果/审计/终态；失败回滚，终态重试跳过。SHA-256 名单和奖项摘要用于追溯，不等于外部公平性证明。

调度器启动补处理，之后每 30 秒检查，遵循 `BACKGROUND_TASKS_DISABLED`；失败下一周期重试，不依赖访问。正式发布前做 SQLite online backup；回退应用时保留抽奖表和开奖记录，避免重新开奖。并发、边界、回滚、补处理、图片与真实路由鉴权的测试入口为 [lottery.test.js](../server/tests/lottery.test.js)。

### 共享界面、多端与部署

主题来自 `SettingsContext`、`src/index.css` 和共享 helper；i18n 使用 `zh`、`en` 与 `public/locales/`。全屏弹层通过 `BodyPortal` 脱离 transform 容器，配合 `100dvh`、滚动锁、安全区及返回关闭。动效复用共享 token，导航正确优先于退出动画。

Web/PWA 为产品主实现，微信、Android、iOS 和其他壳按平台桥接上传、分享、登录与返回，不复制业务数据。根 Service Worker 不接管 `/lingzhi/`、`/code/` 等独立应用；认证、后台及带 Authorization 的 API 使用 NetworkOnly。动态 chunk 失效只作有界恢复，避免循环刷新。

本地前端固定 `5180`，后端 `5181`，开发模式关闭后台任务，安装与代理说明见 [README](../README.md#本地开发)。生产 `master` 推送触发 [deploy.yml](../.github/workflows/deploy.yml)，检查、构建并生成包含 SHA 和校验信息的发布包。`ZJU_DEPLOY_TRANSPORT=local` 时由本机中转，否则由 GitHub 直传；共用 `deploy/deploy-release.sh`、PM2 和 Caddy。

发布保留私有配置、上传和数据库，互斥执行并检查健康；失败回退应用和运行文件，不自动回退数据库。推送成功、CI 通过和实际部署分别确认。操作及恢复见[本机中转部署](操作手册/本机中转部署.md)，原生打包与验收见[操作手册](操作手册/)。
