# 拓途浙享开发禁区

> 文档状态：当前跨任务工程护栏
>
> 使用方式：只记录现在仍然不能采用的做法；历史原因查看[项目决策记录](./归档/项目决策记录.md)。

本文不是错误日志。每条禁区都应尽量由领域合同、Schema、自动化测试、lint、隐私扫描或运行时门禁执行；已经失效的条目直接修改或删除，不追加时间线。

## 1. 产品与真源

### 1.1 禁止把拓途浙享缩成信息聚合站

- 活动、社区、项目、浙客松、profile 与后台属于同一个生态转化系统。
- 新功能必须说明怎样帮助机会发现、可信连接、项目实践、成果沉淀或生态治理。
- 不用栏目数量、媒体数量和访问量替代有效连接与后续行动。

### 1.2 禁止为栏目建立平行内容系统

- AI 社区维持统一内容心智，网页、文档、CLI 和微信采集进入共享审核与归属链。
- 不恢复独立新闻站、教程站、组队站或微信群内容真源。
- 社区当前多表是兼容债务，不是继续复制内容池的理由。

### 1.3 禁止把项目降级为帖子或装饰卡片

- 项目使用一等 project card、状态、主体和成员关系。
- 组队帖、自定义主页卡片、收藏记录和分享海报都不能拥有项目事实。
- 项目广场前台存在时，后台必须有相应治理路径。

### 1.4 禁止用媒体文件替代业务关系

- 赛事作品、项目成果、照片和视频必须通过显式 event/campaign/project/profile 关系连接。
- 不只靠文件名、标签、静态数组或页面分组判断归属。
- legacy media 依赖未确认前不做破坏性迁移。

## 2. 身份、权限与合作关系

### 2.1 禁止把账号和公开主体混为一体

- `users` 负责登录账号；`profiles + profile_members` 负责个人和组织主体。
- 数字名片、主页和组织目录是 profile 投影，不建立名片账号或组织副本。
- 公共 profile 目录不批量枚举自动生成的个人账号、学号、手机号或随手昵称。

### 2.2 禁止用一个 role 表达全部权限

- `account_type`、`review_permission`、`role/admin_scope` 分别表达账号主体、发布审核和后台访问。
- 组织账号不自动是管理员，免审核不自动拥有后台，合作方不自动获得发布权限。
- 前端隐藏按钮不能代替后端权限校验。

### 2.3 禁止根据 profile 存在推断合作方

- 组织可发布活动、接受归属，不等于生态或浙客松合作方。
- About、黑客松和品牌背书只消费明确的 `core_partner` 等 partner scope。
- 活动提供方、普通组织和合作伙伴的前台表达与后台权限分别判断。

### 2.4 禁止无审计迁移历史归属

- 历史内容所有权迁移先生成候选、别名和证据，再人工确认。
- 名称、地点、标题或上传者只能作为证据，不能单独决定所有权。
- 不通过删除重建或复制内容实现归属迁移。

## 3. 搜索、AI 与采集

### 3.1 禁止合并全站搜索与活动推荐

- 搜索服务主动查询和跨模块发现；推荐服务画像驱动的机会决策。
- 两者可以共享 AI runtime、模型和遥测，但保留独立输入、排序、解释、反馈和产品入口。
- 长期活动偏好在用户资料维护，不在推荐面板另建资料真源。

### 3.2 禁止把轻量索引宣传成 embedding 或 RAG

- `resource_search_index.vector_json` 当前是轻量词元/token-hash 表示。
- 产品文案、注释、后台和对外材料都不得称为真实向量语义检索。
- 接入 embedding 时替换索引实现和评测，不轻易改变前端搜索结果协议。

### 3.3 禁止让 AI 直接写正式业务事实

- 搜索解析、活动推荐、微信文章提取和治理扫描默认产生条件、建议或候选。
- 内容发布、主体归属、权限、迁移和审核仍经过正式 controller/service 与用户或管理员确认。
- provider 失败、结构非法和质量不足必须明确区分，不用兜底内容伪装成功。

### 3.4 禁止把“AI 治理”包装得大于真实能力

- 模型配置、活动元数据扫描和 Agent registry 不等于完整内容、推荐、搜索与安全治理。
- 未闭环能力显示只读、实验性或待接入状态。
- AI 完成判断必须有 golden、live、压力、错误恢复或长期效果证据。

### 3.5 禁止把微信登录现场当成采集真源

- 公众号采集使用持久账号、run、article、parse/review 状态。
- 浏览器 Cookie、二维码现场和单次 Playwright 页面只是采集基础设施。
- 登录成功、文章抓取、解析成功、审核通过和正式发布是不同状态。

## 4. 数据、API 与安全

### 4.1 禁止在 controller 或热请求路径改表

- schema 变化进入 `ensureCoreSchema`、`runMigrations` 或 `config/migrations`。
- 迁移必须幂等、可备份、可回退并暴露失败。
- controller 发现缺表缺列时应报错，不现场 `ALTER TABLE` 掩盖部署问题。

### 4.2 禁止把 seed 或本地数据库当成唯一 schema

- 当前 schema 由核心建表与正式迁移共同决定。
- `seed.js`、旧 overview、某个本地 `database.sqlite` 和历史备份都不能覆盖迁移代码。
- 数据修复前先核对生产 schema、迁移版本和恢复路径。

### 4.3 禁止默认重试写操作

- API client 只可默认重试安全读取。
- 写操作只有在领域幂等、幂等键和重复回执明确时才能显式重试。
- 上传、报名、收藏、审核和迁移不能因网络重试产生重复事实。

### 4.4 禁止把长期 token 作为默认行为

- 默认 token 存入 `sessionStorage`；只有用户明确选择持久登录才使用 `localStorage`。
- 登录、登出、微信回执和多端桥接共享同一 token storage helper。
- 不在 URL、日志、公开文档和前端静态配置中暴露 token 或密钥。

### 4.5 禁止向公开仓库提交内部资料

- 不提交数据库、WAL、备份、用户上传、办公文档、商业计划、内部文书、融资或路演材料。
- 不提交 `.env`、微信 AppSecret、AI key、签名证书、用户身份信息、AI memory、会话记录和本地生成产物。
- 每次推送显式暂存任务文件，并检查 ignored-but-tracked 与大文件边界。

## 5. 前端、多端与缓存

### 5.1 禁止让路由退出动画阻塞新页面

- 全站路由切换不能依赖旧页面所有嵌套动画完成。
- 出现“URL 已变但旧内容停在 opacity 0”时先查路由级 `AnimatePresence mode="wait"`。
- 页面可以保留入场动画，但导航正确性优先。

### 5.2 禁止复用已经占用的深链参数

- 文章、帖子、新闻、音乐和其他复合页资源使用各自明确参数。
- 合并栏目或迁移旧路由前，先搜索目标页所有 query/hash 消费者。
- 兼容重定向必须用浏览器验证不会误开兄弟模块。

### 5.3 禁止只用 Clipboard API 支撑传播

- 名片、邀请和分享链接至少提供 Clipboard API、传统复制和可选择手动文本的有界降级。
- 复制成功和权限失败都要真实验证。
- 失败不能只显示 Toast 而不给用户可操作内容。

### 5.4 禁止只加 z-index 修移动弹层

- 检查 portal 挂载点、祖先 transform、`100dvh`、scroll lock、底部导航和返回行为。
- 全屏弹层优先挂到 `body`，并保留主题和语义上下文。
- 移动端取消分屏时同时检查外层高度、内部 flex 居中、横向轨道和 snap。

### 5.5 禁止用页面补丁扩张主题系统

- 白天/黑夜问题先检查 theme token、背景、canvas、fallback、overlay 和 active state 全栈。
- 共享组件和语义 token 优先于逐页颜色覆盖。
- 不用大量截图猜测根因；先代码、DOM 和日夜分支对比，再做代表性视觉验收。

### 5.6 禁止让根 Service Worker 接管同域子应用

- `/lingzhi/`、`/code/` 和其他独立应用必须进入 `navigateFallbackDenylist`。
- 新子应用同时检查 Caddy location、Service Worker 导航回退和 runtime cache。
- 验收必须包含已被旧 Service Worker 控制的标签页点击导航，不只测无痕直接请求。

### 5.7 禁止给不同平台增加并列可见按钮

- 上传、分享、登录、文件选择和打开页面保持同一用户入口。
- 微信小程序内部走小程序原生桥，网页走 Web API 与网页降级。
- 平台分流是运行时实现，不是两套产品信息架构。

### 5.8 禁止让移动端次级操作失去入口

- 代码中存在排序、筛选、更多菜单或抽屉时，页面必须提供稳定、可见、可返回的打开入口。
- 次级页面进入 More/Profile，不把桌面导航机械堆进底栏，也不让用户依赖隐藏手势。
- 移动端验收至少检查入口可见、打开/关闭、返回键、遮罩和底部导航遮挡。

### 5.9 禁止各组件散写动效

- 新增页面和组件优先复用共享 motion token、动画工具和 `prefers-reduced-motion` 规则。
- 不为单个页面重复创建互相冲突的时长、缓动和按压比例，也不把尺寸、布局流和高成本模糊作为默认动画属性。
- 只有表达全新交互语义时才扩展共享动效系统，并补对应的局部验收。

## 6. i18n、验证与部署

### 6.1 禁止通过不可靠终端编码写 locale

- 修改中文与英文 JSON 使用 `apply_patch` 或明确 UTF-8 的结构化工具。
- 不用可能损坏中文的 PowerShell here-string/内联脚本直接写资源。
- 修改后执行 `JSON.parse`，扫描 `??`、替换字符、英文页 CJK 和关键符号损坏。

### 6.2 禁止把局部检查写成完整验证

- 构建通过不等于真实浏览器、微信、Android、iOS、AI provider 或生产通过。
- UI 任务验证中英文、桌面、移动、白天和黑夜的实际影响范围。
- 启动任务必须确认进程持续、HTTP 成功、后端健康和页面可见。

### 6.3 禁止用代码图谱替代源码与运行时

- `.codebase-memory` 等图谱只做第一层导航。
- 最终结论回到 `rg`、源码、diff、测试、DOM、浏览器和真实接口。
- 图谱找不到或索引过时时立即切换，不在工具里空转。

### 6.4 禁止重载已退役的反向代理

- 当前生产入口是 Caddy，发布前 `caddy validate`，发布后 reload 并检查 active。
- 不把 Nginx 的停止状态误报为生产失败，也不在流水线恢复旧 Nginx 步骤。
- 网关迁移同时搜索 CI/CD、systemd、监控和运维文档中的旧服务名。

## 7. 维护门

新增禁区必须满足至少一项：高代价错误曾重复发生；约束跨模块且无法只靠局部代码表达；未来开发者或 AI 很可能再次采用错误方案。

可以由单个测试、类型系统或局部注释完整表达的细节，不追加到本文。禁区失效或被更准确合同替代时，直接修改原条目；历史原因交给 Git、OpenSpec 和项目决策记录。
