# 归档说明

本目录存放已经退役、暂不采用或不再作为当前施工入口的规格、计划和决策材料。

归档文件的作用是保留历史上下文，便于追溯“过去考虑过什么、为什么停止或改变”。它们不是当前产品真源，也不是日常事实层、经验层或进度日志。

## 当前真源

判断现在应该怎么做时，优先读取：

1. [产品蓝图](../产品蓝图.md)：产品定义、核心闭环和长期边界。
2. [产品状态](../产品状态.md)：当前阶段、成熟度、缺口和下一步。
3. [技术架构](../技术架构.md)：代码、数据、运行链和技术约束。
4. [开发禁区](../开发禁区.md)：跨任务仍然有效的护栏。
5. `openspec/changes/` 与正式 spec：具体功能合同。

## 如何提取价值

读取归档时只做定向提取：

- 稳定产品结论回写产品蓝图或产品状态。
- 稳定技术约束回写技术架构；重复出现且代价高的错误回写开发禁区。
- 有证据的成功、失败和反馈先写本地 `docs/事实.md`，多个事实归纳后再写本地 `docs/经验.md`。
- 具体字段、接口、状态和验收合同进入 OpenSpec 或正式 spec。

原文件不因提取而删除或覆盖；历史方案与当前真源冲突时，以代码、运行结果、正式文档和 OpenSpec 为准。
