# 归档说明

```text
docs/归档/
├── README.md                 归档边界与使用方式
├── 提取清单.md               各历史文件的处理状态与提取去向
├── 项目决策记录.md           过去为什么这样决定
├── 历史规格/                 已退役的独立规格
├── 旧版设计/                 已退役的设计规格与施工计划
└── 旧版项目文档/             曾经作为项目入口、现已退役的文档
```

本目录只保存已经退役、暂不采用或不再作为当前施工入口的材料。它用于追溯过去考虑过什么、为什么改变，以及当前结论从哪里提取而来；不承担项目状态、长期规则或任务进度。

## 当前判断入口

1. `README.md`：人类上手入口。

2. `docs/产品蓝图.md`：产品定位、核心闭环和长期边界。

3. `docs/产品状态.md`：当前阶段、成熟度、缺口和下一步。

4. `docs/技术架构.md`：代码、数据、运行链和技术边界。

5. `AGENTS.md`：本项目长期有效的协作与执行规则。

6. `openspec/changes/` 与正式 spec：具体功能合同。

## 历史材料怎样重新进入当前系统

```text
历史材料
→ 对照代码、运行结果和当前真源核验
├── 稳定产品结论 → 产品蓝图或产品状态
├── 稳定技术结论 → 技术架构
├── 稳定项目规则 → AGENTS.md
├── 具体功能合同 → OpenSpec 或正式 spec
└── 真实执行结果 → 本地 docs/事实.md
```

一次历史表述不能直接升级为当前规则。提取完成后保留原文件，并在 `提取清单.md` 记录去向；历史材料与当前真源冲突时，以代码、数据库 schema、运行结果、正式文档和 OpenSpec 为准。
