## 2026-08-04 项目文档按职责与生命周期治理

- 状态：当前有效。
- 决策：`AGENTS.md` 给 AI，`README.md` 给人；产品蓝图、产品状态、系统架构、开发禁区分别维护当前产品、进度、代码和禁区。
- 决策：具体开发使用 OpenSpec 或必要 spike；完成后把稳定结论回流当前真源，过程留在 Git 和归档规格。
- 决策：不再维护正向经验、错误时间线和项目决策三份默认 AI memory；高代价错误直接提炼为开发禁区并增加自动化保护。

## 2026-07-25 公开仓库隔离内部资料

- 状态：当前有效。
- 决策：公开仓库只承载产品代码、公开资源、必要规格和公开协作文档。
- 决策：商业计划、内部文书、办公文档、用户上传、数据库、密钥、AI memory、会话记录和本地生成产物只留本地。
- 影响：提交前必须检查隐私路径、ignored-but-tracked 和大文件，显式暂存任务文件。

## 2026-07-09 学习资源采用用途栏目与元信息精筛

- 状态：当前有效。
- 决策：资源区一级栏目按往年题、复习提纲、课件摘要、笔记整理、题解/答案和其他资料等用途划分。
- 决策：课程、教师和学期是二级筛选与元信息，不从自由标签临时推断一级栏目。

## 2026-07-07 数字名片是 profile 的传播层

- 状态：当前有效。
- 决策：个人与组织名片复用 profile、主页和公开 profile card，不新增名片账号或身份表。
- 决策：传播层支持二维码、链接、图片和系统分享；浏览器拒绝剪贴板时必须提供手动复制降级。

## 2026-07-06 多平台能力使用同一按钮运行时分流

- 状态：当前有效。
- 决策：上传、分享、登录、复制和文件选择保持同一用户入口。
- 决策：微信小程序 WebView 内走原生桥，网页走 Web API，Android/iOS 壳复用同一产品和 API。

## 2026-07-06 用户系统采用三轴权限

- 状态：当前有效。
- 决策：`account_type` 表达账号主体，`review_permission` 表达发布审核能力，`role/admin_scope` 表达后台访问。
- 决策：组织主体继续由 `profiles + profile_members` 承载，合作展示由 `ecosystem_partners.partner_scope` 承载。
- 边界：组织、免审核、管理员和合作方身份互不自动推导。

## 2026-07-06 About 页承载拓浙 AI 生态官网

- 状态：当前有效。
- 决策：About 的主语是拓浙 AI 生态，负责说明生态、支持资源、运行机制与参与方式。
- 边界：拓途浙享是生态数字底座，不把活动、社区或 App 栏目列表误写成整个生态。

## 2026-07-05 组织主体与合作身份分层

- 状态：当前有效。
- 决策：组织可以拥有 profile、发布活动和接受内容归属，但不自动成为生态或赛事合作方。
- 决策：`partner_scope` 显式区分核心合作伙伴与活动提供方，About、黑客松和品牌背书只消费相应范围。

## 2026-07-02 拓浙 AI 生态是网站根业务定位

- 状态：当前有效。
- 决策：拓途浙享不是普通活动聚合或内容社区，而是生态的数字底座和公共入口。
- 决策：产品围绕社区聚人、项目育人、赛事选才和产学连接，把学生、组织、学校资源、真实需求和成果放入同一网络。
- 边界：平台负责触达、连接、记录和运营，不在公开产品中承载合同、付款、法务和内部商业管理。

## 2026-06-29 用户系统先做账号与身份控制中心

- 状态：当前有效。
- 决策：复用既有 users、profiles、成员、认证、投稿和成果关系，通过聚合概览加厚用户中心。
- 边界：不新增平行账号中心，资料完整度只做引导，不自动成为权限门槛。

## 2026-06-29 Android 优先复用 Web/PWA 包装

- 状态：当前有效。
- 决策：Android 以 `android-twa/` 中的 TWA/WebView 包装交付，优先保障域名绑定、签名、下载和安装。
- 边界：没有明确原生需求时不重写 Web 页面与业务状态。

## 2026-06-29 全站索引是补充召回层

- 状态：当前有效。
- 决策：`resource_search_index` 补充活动、社区和媒体的公开资源召回，保持 `/api/search` 结果合同稳定。
- 边界：`vector_json` 是轻量 token-hash/词元表示，不宣称真实 embedding 或 RAG。

## 2026-06-29 身份归属采用多主体 profile 关系

- 状态：当前有效。
- 决策：一条内容可以同时关联上传者、发布主体、主办主体和历史归属，不复制内容。
- 决策：历史平台代发内容通过候选、别名、人工确认和审计逐步迁入认证组织 profile。

## 2026-06-29 AI 社区采用统一内容系统

- 状态：当前有效。
- 决策：技术分享、求助问答、新闻热点和组队协作共享统一发布、审核和用户投稿管理心智。
- 边界：旧路由可以兼容，不恢复独立新闻热榜、教程站或组队系统。

## 2026-06-25 平台底座采用渐进式分层

- 状态：当前有效。
- 决策：目标后端分层为 route、controller、application/domain service、data/config/helper；前端新代码优先进入 app、features、shared。
- 决策：schema 进入正式 migration，写请求默认不自动重试，token 默认 session-only，移动全屏弹层走 body portal。
- 边界：不通过一次性微服务、数据库、TypeScript 或 UI 框架重写解决历史债务。

## 2026-06-08 白天模式采用纯净底色与克制粉紫点缀

- 状态：当前有效，具体实现仍由当前主题 OpenSpec 和代码校准。
- 决策：白天模式以纯白或极浅表面为基础，粉紫只用于主操作、选中态和少量光晕。
- 边界：避免大面积灰底、蓝绿渐变、半渐变按钮和过度胶囊化。
