## 1. 当前阶段判断

拓途浙享已经跨过“校园媒体与活动聚合原型”阶段，进入**生态多业务可用后的治理收束期**。

活动、AI 社区、项目广场、浙客松、个人与组织 profile、搜索推荐、微信采集、管理员后台和多端壳层都有真实代码与入口。当前主要问题不是栏目是否存在，而是：

1. 前台已经形成生态业务；后台已完成六域导航、紧凑总览、内容采集、设置分类、项目治理和 AI 能力分区的第一轮重排，主要剩余规格归档债与真实运行观察。
2. 身份、项目和赛事成果主链基本成立；项目长期事实与单届赛事作品已显式连接，仍需真实生产数据补录策略、治理入口和长期效果验证。
3. OpenSpec 活动区存在多项“代码完成但未归档”或只剩外部环境验收的变更，当前状态噪音较大。
4. 数据迁移、社区多表兼容、主题补丁和多端平台差异仍有长期技术债。
5. 产品能够记录参与和成果，但“有效连接是否持续转化为项目、人才和合作”的长期指标尚未闭环。

## 2. 成熟度口径

| 状态     | 含义                                                     |
| -------- | -------------------------------------------------------- |
| 稳定基座 | 正式真源、权限、异常合同和主要回归稳定，可被其他能力依赖 |
| 主链可用 | 正常路径已进入真实产品，仍有兼容、治理或完整验收缺口     |
| 局部闭环 | 已有纵向样板，但未覆盖所有入口、异常矩阵或长期效果       |
| 在建     | 正在由活动 OpenSpec 实施，不能作为完成能力承诺           |
| 待验证   | 实现或设计存在，但缺真实账号、真机、生产或长期效果证据   |

成熟度描述当前证据，不是百分比，也不替代 OpenSpec 任务状态。

## 5. 当前攻坚顺序

### 5.1 先清理规格状态债

1. 对 6 个 Complete change 逐项核对任务、正式 spec 和当前代码。
2. 归档确认完成的 change，并再次运行 `openspec validate --all`。

### 5.2 当前主攻后台治理

1. 六域导航、模块状态、紧凑总览已经落地；继续保持 URL tab 兼容和桌面/移动行为一致。
2. 内容采集首屏已按状态、最近采集和候选内容静态组织，不使用流水线规定操作顺序；当前只承诺学院、社团等微信公众号来源，不把它描述成通用网站爬虫。
3. 站点设置已分类收纳；继续保持三轴权限、合作方层级和 AI 社区统一内容合同，不借重排重做领域模型。
4. 项目广场后台已覆盖状态、举报、归属、下架和恢复；AI 能力治理已分为能力状态、活动元数据和模型配置，并标清只读诊断与基础设施边界。

### 5.3 收束前台纵向闭环

```text
项目广场最终验收
-> 浙客松媒体与成果关系
-> 移动端真实设备交互
-> iOS/Android/微信多端发布门
```

不要在这些主链闭合前新增私信、第二社区、第二身份系统或大规模原生重写。

## 6. 横向风险

| AI 名称大于能力        | 搜索、推荐、治理入口分工                            | live 评测、错误恢复和真实长期效果             |
| 多端形成第二产品       | 同按钮运行时分流、共享 API                          | 微信、Android、iOS 真机是否行为一致           |
| 数据迁移债             | `ensureCoreSchema + runMigrations` 和备份           | controller/热路径遗留 schema 修补是否继续退出 |
| 缓存与部署跨应用干扰   | Caddy、Service Worker denylist、动态 chunk 有界恢复 | 旧受控标签页和新同域子应用场景                |

## 7. 状态更新门

只在以下情况更新本文：

- 能力首次进入正式主链。
- 主链从局部闭环升级为稳定基座。
- 关键缺口、风险或当前主攻发生变化。
- OpenSpec 新建、归档、替换或范围发生实质变化。
- 真实账号、真机、生产或长期验证推翻原有完成判断。

普通提交、测试数字、单个 bug、每日进度和历史过程不进入本文。它们留在 Git、OpenSpec、测试或归档材料中。
