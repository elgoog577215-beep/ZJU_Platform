## 1. 当前阶段判断

拓途浙享已经跨过“校园媒体与活动聚合原型”阶段，进入**生态多业务可用后的治理收束期**。

活动、AI 社区、项目广场、浙客松、个人与组织 profile、搜索推荐、微信采集、管理员后台和多端壳层都有真实代码与入口。当前主要问题不是栏目是否存在，而是：

1. 前台已经形成生态业务；后台六域导航、紧凑总览、内容采集、设置分类、项目治理和 AI 能力分区已经进入主链，剩余重点是真实运行观察，不再把历史规格归档债当作产品任务。
2. 身份、项目和赛事成果主链基本成立；项目长期事实与单届赛事作品已显式连接，仍需真实生产数据补录策略、治理入口和长期效果验证。
3. OpenSpec 活动区已经从大量完成项和旧方案收缩为 4 个仍有明确未完成门的变更；后续只为跨轮次复杂工作保留活动 change。
4. 数据迁移、社区多表兼容、主题补丁和多端平台差异仍有长期技术债。
5. 产品能够记录参与和成果，但“有效连接是否持续转化为项目、人才和合作”的长期指标尚未闭环。

## 2. 成熟度口径

| 状态     | 含义                                                     |
| -------- | -------------------------------------------------------- |
| 稳定基座 | 正式真源、权限、异常合同和主要回归稳定，可被其他能力依赖 |
| 主链可用 | 正常路径已进入真实产品，仍有兼容、治理或完整验收缺口     |
| 局部闭环 | 已有纵向样板，但未覆盖所有入口、异常矩阵或长期效果       |
| 在建     | 正在由活动 OpenSpec 实施，不能作为完成能力承诺           |
| 待验证   | 实现或设计存在，但缺真实账号、真机、生产或长期效果证据   |

成熟度描述当前证据，不是百分比，也不替代 OpenSpec 任务状态。

## 5. 当前攻坚顺序

### 5.1 当前主攻内容来源收尾

为 WeWe RSS 配置至少一个真实 feed，完成生产镜像、Atom/TRPC、正文图片、来源提醒和恢复动作验证。验证不到真实 feed 时保持活动，不用本地 mock 冒充完成。

### 5.2 收束赛事成果关系

确认生产 UI 不再依赖 legacy `competition_media` 后再迁移或归档旧记录；补齐后台事件归属与排序，并完成桌面、移动、返回链、深链、空赛事和未关联媒体的终验。

### 5.3 收束前台纵向闭环

```text
浙客松媒体与成果关系
-> RSS 真实来源与恢复
-> iOS/Android/微信多端发布门
-> 日间主题系统重新对齐后再实施
```

不要在这些主链闭合前新增私信、第二社区、第二身份系统或大规模原生重写。

只在以下情况更新本文：

- 能力首次进入正式主链。
- 主链从局部闭环升级为稳定基座。
- 关键缺口、风险或当前主攻发生变化。
- OpenSpec 新建、归档、替换或范围发生实质变化。
- 真实账号、真机、生产或长期验证推翻原有完成判断。

普通提交、测试数字、单个 bug、每日进度和历史过程不进入本文。它们留在 Git、OpenSpec、测试或归档材料中。
